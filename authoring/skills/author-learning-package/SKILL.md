# Author one learning package

## Inputs

Read, in order:

1. `governance/state/LOAD-STATE.md` and the current manifest;
2. `authoring/agents/learning-material-author.md`;
3. `authoring/workflow/content-author-workflow.md`;
4. both files in `authoring/standards/`;
5. the assigned work package and every `Context manifest` file.

## Ownership and stop conditions

Confirm that the current action authorizes the package. Treat `Ownership`, file
count, phase order, non-goals and stop conditions as hard boundaries. If Gate 0
is required, confirm it before dependent authoring; stop when it is unavailable
or failed.

## Work

Create only required artifacts. Preserve semantic IDs and do not claim coverage
without a matching target/role relationship. Verify technical claims with
primary sources, keep reader-facing text autonomous, and leave outputs in
`review`.

## Handoff and lifecycle boundary

Before handoff run proportional YAML, ID, link/anchor, Markdown, terminology,
coverage and scope checks. Report files, coverage, evidence, decisions, debt and
recommended independent review. Do not run that review or declare acceptance.
