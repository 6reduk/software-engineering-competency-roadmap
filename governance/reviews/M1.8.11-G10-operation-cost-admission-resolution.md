# M1.8.11 — решение оркестратора по G10

## Решение

Содержательный verdict консолидации принят: `accepted_with_changes` — `0 blocker / 0 major / 4 minor / 5 note`. Gate 0, exact pinned stack, порядок `binding → нормализация → оценка стоимости → admission → execution`, tenant/disclosure boundary, measurement envelope, Abuse L1–L3 coverage и различие kata/project подтверждены двумя независимыми профилями.

Перед acceptance выполняется один локальный пакет [`M1.8.11a-G10-findings-closure.md`](../work-packages/M1.8.11a-G10-findings-closure.md). В него входят обязательные C-1–C-4 и три дешёвых редакционных уточнения C-5–C-7. Повторный полный G10 не требуется: техническое evidence не зависит от этих правок. После handoff автора оркестратор проводит точечный verification- и acceptance-pass.

Gate G10 пока не считается пройденным. Пять материалов остаются в `review`; программный статус и module gate не меняются.

## Disposition findings

| Finding | Решение | Обоснование |
|---|---|---|
| C-1, minor | Исправить до acceptance | Требование строгих типов должно явно предупреждать, что дефолтный lax-режим Pydantic принимает некоторые `str`/`float`/`bool` как `int`; строгий контракт требует явной конфигурации модели и проверок вариантов формы. |
| C-2, minor | Исправить до acceptance | Без собственного `RequestValidationError` handler дефолт FastAPI не выполняет закреплённые media-type и disclosure semantics и может вернуть исходное значение из `input`. |
| C-3, minor | Исправить до acceptance | `allowlist`, `harness` и `seam` смыслообразующие; их нужно объяснить обычным русским языком при первом употреблении или в локальном словаре. |
| C-4, minor | Исправить до acceptance | Внутренний код `S05` не должен быть необходим читателю; project-spec получает человеческое название и разрешающуюся ссылку на принятый brief. |
| C-5, note | Исправить тем же проходом | `Recovery` в этом эксперименте означает отсутствие накопленного эффекта отказов и сохранность допустимой операции, а не восстановление уже израсходованных ресурсов. |
| C-6, note | Исправить тем же проходом | После обеих Mermaid-схем нужно явно назвать намеренно опущенные ветки input-invalid и audit, чтобы схема не читалась как полная модель. |
| C-7, note | Исправить тем же проходом | Второй tenant нужен для isolation evidence, а минимум 3000 Orders — для воспроизводимой выборки; это нужно сказать рядом с требованиями project-spec. |
| C-8, note | Отложить до обновления baseline | Текущий runtime evidence принято. При следующем обновлении закреплённого стека `versions` обязан включать фактическую версию `httpx`/`httpx2`, поскольку TestClient warning относится к этой зависимости. |
| C-9, note | Зафиксировать решением, без правки материалов | Предзаполненные dispositions applicability matrix допустимы только после package-level adjudication. L2 evidence участника остаётся самостоятельным: реализация, ссылки на наблюдения и decision record. Это не универсальный шаблон будущих slices. |

## Принятые границы evidence

- Recovery population после 100 bypass-запросов доказывает отсутствие учтённой работы у отклонений и сохранность legitimate use. Она не доказывает освобождение ресурсов, которых эти отказы не расходовали, и не заменяет quota/rate evidence.
- Синтетическая cell model и два counters достаточны для L3 только внутри объявленного envelope: воспроизводимые abuse paths, reject-before-work, tenant isolation, сохранность допустимой операции и явно названные residual risks. Они не являются моделью SQL scan, response bytes, peak memory, concurrency или storage cost.
- Abuse L2 подтверждает рассмотрение четырёх adjudicated категорий, а не внедрение четырёх механизмов. Для `quota/rate` и `untrusted target` допустимость `not applicable` основана на явной границе сценария и сохранённом residual risk.
- Slice не закрывает S14 полностью: aggregate quota/rate и callback/untrusted-target/SSRF остаются отдельными будущими bounded packages со своими readiness gates.

## Условия acceptance-pass

- C-1–C-7 имеют отдельные видимые исправления и mapping в handoff автора.
- Semantic IDs, 13 relationships, 4 targets, coverage roles, версии, endpoint, формула, threshold, populations, counters и регистрации не меняются.
- Пять материалов остаются в `status: review` до решения оркестратора.
- Kata и project не получают готовую реализацию или ImplementationReference.
- После точечной проверки оркестратор переводит пакет и материалы M1.8.11 в `accepted`, фиксирует G10 и назначает refresh delivery plan; module gate автоматически не присваивается.
