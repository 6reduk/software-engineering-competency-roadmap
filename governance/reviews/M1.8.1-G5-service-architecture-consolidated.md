## Консолидированные findings

Источник: 🔵 — GLM (профиль A); 🟡 — Kimi (профиль B). Полные evidence и рекомендации — в исходных review; здесь сжатая запись с диспозицией.

### Minor

**C-1 (🔵 GLM + 🟡 Kimi F-1, объединено). README: retry отнесён к «будущим пакетам».**
В разделе «Границы пакета» предложение «Transaction, unit of work, outbox, retry и consistency относятся к будущим пакетам» неточно: retry-граница downstream client — уже принятое покрытие M1.7 (R2 `explain`, R4 `practice/assess`, оба `accepted`), и тот же README в разделе «Кому и что потребуется» сам называет её готовой границей. Формулировка противоречит реализации C-5 внутри пакета (kata non-goals и project verification contract ссылаются на принятый материал) и может навести читателя на мысль, что retry нигде в треке не разобран.
Диспозиция: **fix-проход** — исключить `retry` из перечня будущих пакетов (оставив transaction/unit of work/outbox/consistency, при желании добавив caching/idempotency по образцу work package) либо заменить ссылкой на принятый материал о downstream client boundary. Правка одного предложения; coverage, структура и остальные файлы не затрагиваются.

### Note

**C-2 (🔵 GLM). Kata: подсказка 2 частично дублирует задание.**
Подсказка 2 предлагает «сформулировать таблицу business inputs → eligibility», хотя минимальная таблица поведения уже выдана участнику в разделе «Задача». Реальная ценность подсказки — вторая фраза о вычислимости решения обычным вызовом Python без session и client.
Диспозиция: **fix-проход (опционально)** — переформулировать вокруг собственного вклада: «добейтесь, чтобы решение из выданной таблицы вычислялось обычным вызовом Python без session и client». Допустимо перенести в backlog без влияния на принятие.

**C-3 (🟡 Kimi F-2). Проверка Ownership выполнена файловым способом, без Git.**
`.git` в корне workspace — пустой каталог, рабочего Git repository нет; work package прямо допускает этот режим. Файловые проверки пройдены: ровно пять файлов в slice-каталоге, разделы M1.5/M1.7 в `coverage-map.md` не изменены, одна строка регистрации в `curriculum/tracks/b2/README.md` со статусом `review`.
Диспозиция: **зафиксировать ограничение**; при появлении рабочего Git repository повторить ownership-проверку через `git diff`/`git status`. Это ограничение процесса, а не дефект пакета.
