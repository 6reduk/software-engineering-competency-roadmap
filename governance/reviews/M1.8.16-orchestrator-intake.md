# M1.8.16 — orchestrator intake

## Verdict

`accepted_for_review`: `0 blocker / 0 major / 0 minor / 1 note`.

Обновлённый delivery plan допускается к двум независимым профилям G15. Intake подтверждает внутреннюю целостность и готовность документа к review, но не принимает очередь, выбор External Integration/S08, будущий client substrate или A3/B5 readiness.

## Проверенный scope

- План имеет `status: review`, snapshot 2026-09-08; по handoff автора изменён только `curriculum/tracks/b2/module-delivery-plan.md`.
- Независимый пересчёт YAML подтверждает: 52 accepted artifacts, 240 relationships = 20 capability-level `reference` + 220 outcome-level, 58 покрытых и 11 непокрытых outcomes из 69, семь `probe-only`.
- Ролевые итоги совпадают: `reference 20 / explain 53 / probe 55 / practice 27 / integrate 29 / assess 56`.
- M1.8.15 добавляет пять artifacts и 13 relationships; впервые покрыт Delivery L1. Delivery L2/L3 получили собственный S11 flow, но Evolution, Compatibility, Verification, B6/B7 и Delivery L4 новых связей не получили.
- Safe Service Evolution переведён `not-started → partial`; итог `0 complete / 9 partial / 1 not-started / 0 blocked`. Единственный `not-started` — External Service Integration.
- Internal hard DAG отделён от внешних readiness gates и от proficiency соответствующих вертикалей.
- Сравнены шесть кандидатов; выбран ровно один S08 package в `b2.module.external-service-integration`.
- Decision brief задаёт одно центральное действие: различить корректное предметное отсутствие данных, невалидный ответ и отказ одной read-only dependency на client boundary. Fan-out, pool, cancellation и общий resilience course исключены.
- Будущее primary coverage ограничено External Integration L1/L2. Нулевой прирост unique outcomes указан честно: ценность заявлена как собственное execution-oriented evidence последнего `not-started` модуля.

## Note intake

**I-1 — registration hygiene.** Заключительный абзац M1.8.15 в `curriculum/tracks/b2/coverage-map.md` всё ещё говорит, что пять материалов находятся в `review` и не входят в accepted totals. Канонические YAML и G14 acceptance подтверждают `accepted`; план правильно не использовал эту фразу как источник подсчёта и вынес расхождение в open questions. Исправление выполняется оркестратором после G15 вместе с acceptance/correction pass, чтобы не менять review baseline в ходе независимой проверки.

## Контрольная гипотеза G15

Review должен независимо подтвердить либо опровергнуть:

1. числа `52 / 240 / 20+220 / 58+11 / 7`, новый Delivery L1 и membership Safe Service Evolution `12/10`;
2. переход только Safe Service Evolution и итог состояний `0/9/1/0`;
3. неизменность internal hard DAG и локальность B6/B7 readiness M1.8.15;
4. приоритет External Integration/S08 над HTTP Runtime, callback/SSRF, aggregate quota/rate и completion-tail именно сейчас;
5. содержательную новизну response-decoding/business-absence boundary относительно R2/R4/R5 и общего error mapping S10;
6. boundedness: одна read-only Pricing operation, одна client boundary, одна попытка по умолчанию, без fan-out/pool/cancellation/SSRF/platform scope;
7. достаточность будущего Gate 0 для закрепления response matrix, client/runtime, реального HTTP evidence, failure injection, timeout/cleanup и applicability A3/B5;
8. оправданность полного learning flow External L1/L2 при нулевом unique-outcome gain и отсутствие overclaim L3/L4;
9. сохранение долгов Evolution L1, L4 outcomes, callback/SSRF, aggregate quota/rate, module gates и ImplementationReference.

## Граница intake

Intake не подтверждает техническую реализуемость будущей Pricing-лаборатории, не выбирает HTTP client, service discovery, retry library или deployment topology и не разрешает произвольные пользовательские URL. Эти решения допустимы только после G15 внутри отдельного Gate 0 authoring package.
