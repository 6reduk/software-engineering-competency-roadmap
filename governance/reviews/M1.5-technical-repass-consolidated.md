## Консолидированные findings

Источник: 🟢 — оба ревью; 🔵 — только GLM; 🟡 — только Kimi. Формулировкиseverity при расхождении принимались по более высокой с обоснованием.

### Minor

**C-1 (🔵 GLM M-1). Нормативное обязательство кэша приписано RFC 9110, но живёт в RFC 9111.**
- Evidence: `learn/compatible-api-change.md:188`, `learn/http-contract-execution-boundary.md:175`; RFC 9111 §4.1: "MUST NOT use that stored response without revalidation unless all the presented request header fields nominated by that Vary field value match".
- Impact: поле `Vary` определено в RFC 9110 §12.5.5, но слово «обязан» в текстах brief опирается на RFC 9111, отсутствующий в списках первичных источников.
- Согласование: Kimi проверил семантику Vary по RFC 9110 и принял её; расхождение не в корректности утверждения, а в полноте ссылки. Решение: сохранить minor.
- Recommendation: добавить RFC 9111 в «Первичные источники» обоих brief или уточнить формулировку (сервер сообщает `Vary` — RFC 9110; кэш обязан учитывать — RFC 9111 §4.1).

**C-2 (🟢 GLM M-2 ≡ Kimi M-2). Два семейства примеров сквозной ситуации.**
- Evidence: `learn/compatible-api-change.md:37-42`, interview — `customer_id: "c-42"`, `{"product_id": "p-7"}`; `kata/…:40-44`, `project-spec/…:69-71` — `"c-17"`, `{"sku": "book-1"}`.
- Impact: одна «сквозная» история Orders API с разными именами полей товара; читатель вынужден перепроверять, та ли это система.
- Recommendation (согласовано): унифицировать имена полей либо одной фразой в README пояснить независимость примеров kata/project-spec.

**C-3 (🟢 GLM M-3 ≡ Kimi N-1, severity повышена до minor). Freshness-метаданные только у learn-документов.**
- Evidence: `last_verified`/`versions` есть только в двух learn; interview (`api-contract-evolution.md:97` — Pydantic v2) и kata (шаг 3) содержат версионно-чувствительные утверждения; module-level `verified_baseline` в `modules.md` не задан.
- Impact: при смене мажорной версии Pydantic/FastAPI не к чему привязать пересмотр interview/kata.
- Согласование: GLM — minor, Kimi — note. Принято minor: утверждение про обязательность поля в interview — ядро вопроса интервью №1, а не passing detail.
- Recommendation: module-level `verified_baseline` (метамодель это предусматривает) либо `last_verified` в каждом артефакте с версионными утверждениями.

**C-4 (🔵 GLM M-4). Ссылки на документацию Pydantic 301-редиректят.**
- Evidence: `learn/compatible-api-change.md:345`, `learn/http-contract-execution-boundary.md:272` → `docs.pydantic.dev/latest/...` (301 на `pydantic.dev/docs/...`).
- Impact: ссылки работают, но домен мигрировал; редирект со временем может исчезнуть.
- Recommendation: обновить URL на `pydantic.dev/docs/validation/latest/...`.

**C-5 (🔵 GLM M-5). Сценарий смешения кэша без оговорки о кэшируемости POST.**
- Evidence: `project-spec/evolvable-orders-api.md:174` (сценарий 8); сквозная операция — `POST /orders`.
- Impact: ответы POST сохраняются общим кэшем только при явной информации свежести (RFC 9111); без оговорки читатель может решить, что общий кэш хранит ответы POST по умолчанию.
- Recommendation: одной фразой оговорить применимость (явно кэшируемые ответы либо read-операции `GET /orders/{id}`).

**C-6 (🟡 Kimi M-1, перепроверено при консолидации). Сокращённый пример ответа валидации FastAPI выдан за фактический.**
- Evidence: `learn/http-contract-execution-boundary.md:34-40` — «реальный клиент получает другой ответ»: `{"detail": [{"loc": ..., "type": "missing"}]}` без `msg`/`input`.
- Impact: фактический ответ FastAPI/Pydantic v2 содержит также `msg` (и обычно `input`, `url`). В материале, который учит сверять документацию с реальностью, сокращённый пример подан как точный — особенно заметно.
- Recommendation: добавить `"msg": "Field required"` или явно пометить пример как сокращённый.

**C-7 (🟡 Kimi M-3, с уточнением GLM). Остаточное расхождение терминологии consumer/producer.**
- Evidence: `learn/compatible-api-change.md:212` аргументирует отказ от producer/consumer в пользу `API caller`/`API provider`; `interview/…:253-254` и `project-spec/…:334` определяют «consumer»/«producer» в локальных словарях.
- Impact: учащийся встречает термины, которые один из документов слайса объявил запутывающими. Локальные словари смягчают, но не снимают вопрос.
- Согласование: GLM зафиксировал терминологию как дисциплинированную (замена мотивирована в тексте learn); Kimi указал остаточный риск для сквозного чтения. Решение: сохранить minor — оба наблюдения верны, риск навигационный, а не фактический.
- Recommendation: в interview/project-spec добавить кросс-ссылку на caller/provider-терминологию learn.

### Note

**C-8 (🟡 Kimi N-2, перепроверено при консолидации; сливается с GLM N-1). Расширение `errors[].pointer` отличается от примера RFC 9457 формой.**
- Evidence: `learn/http-contract-execution-boundary.md:150-152` — `"pointer": "/delivery/window/end"`; RFC 9457 §3 — fragment-форма: `"pointer": "#/age"`, `"#/profile/color"` (сверено с RFC).
- Impact: собственное расширение юридически допустимо, а сам массив `errors` имеет прецедент в RFC; но совпадение имени члена с примером RFC при другой форме значения может смутить.
- Recommendation: принять fragment-форму `#/…` либо зафиксировать одной фразой, что это собственное соглашение сервиса.

**C-9 (🟡 Kimi N-3, перепроверено при консолидации). Описание interview в coverage-map шире фактического coverage.**
- Evidence: `curriculum/tracks/b2/coverage-map.md:41` — «L1–L4 follow-ups»; фактические targets interview — L2–L4 (в coverage interview нет ни одного `-l1-`).
- Impact: навигационное расхождение описания, не контента; вне проверяемого пакета.
- Recommendation: поправить формулировку на «L2–L4».

**C-10 (🔵 GLM N-2). Формулировка про `response_model_include/exclude` избыточно осторожна.**
- Evidence: `learn/http-contract-execution-boundary.md:191` («схема может продолжить описывать полную модель»); документация FastAPI: "the JSON Schema generated … will still be the one for the **complete model**".
- Recommendation: усилить до утвердительной формы.

**C-11 (🔵 GLM N-3). Default scope зависимостей не назван явно.**
- Evidence: схема и текст про `function`/`request` корректны; документация FastAPI задаёт default `request` (очистка после отправки ответа).
- Recommendation: указать default явно, чтобы читатель не предполагал `function`.

**C-12 (🟢 объединяет GLM N-4/N-5 и наблюдения Kimi). Технические детали схемы и coverage — проверены, замечаний нет.**

- Дубли в coverage kata/project-spec (practice+assess, integrate+assess) намеренны; роли соответствуют `governance/architecture/metamodel/relationships-and-invariants.md` и coverage-map построчно (Kimi).

- Разведение уровней kata = L2, project-spec = L3, interview L4 = reasoning probe — соответствует метамодели и README слайса (оба).
