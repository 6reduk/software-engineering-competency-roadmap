# M1.8.16 — решение оркестратора по G15 B2 delivery plan

## Процессуальное решение

По прямому решению владельца программы профиль B пропущен из-за недоступности SaaS-подписки. G15 не считается двухпрофильным review, consolidated-артефакт не создаётся, а отсутствие второго отчёта не маскируется под независимую проверку.

Получен один независимый профиль A с verdict `accepted`: `0 blocker / 0 major / 1 minor / 2 note`. Он полностью подтвердил mechanical coverage, module states и hard DAG. Область пропущенного профиля B — приоритет, новизна и boundedness S08 — оценена оркестратором как risk assessment, а не как второе независимое review.

Итоговое решение: `accepted_with_changes`. До acceptance выполняется один ограниченный пакет [`M1.8.16a-G15-findings-correction.md`](../work-packages/M1.8.16a-G15-findings-correction.md). Повторный профиль A не требуется. Профиль B не становится скрытым долгом, блокирующим этот пакет, но факт исключения сохраняется в audit trail.

## Подтверждённая механика

- 52 accepted artifacts;
- 240 relationships = 20 capability-level `reference` + 220 outcome-level;
- 58/69 covered, 11 uncovered, 7 exact probe-only;
- первые 47 artifacts сохраняют 227 relationships;
- M1.8.15 добавляет 13 relationships и только новый Delivery L1;
- Safe Service Evolution: `12/10`, `not-started → partial`;
- состояния: `0 complete / 9 partial / 1 not-started / 0 blocked`;
- External Service Integration — единственный `not-started` module;
- internal hard DAG содержит 13 рёбер и не меняется из-за Delivery coverage.

## Оркестраторская risk assessment выбора S08

Выбор External Integration принимается по существу. Нулевой прирост unique outcomes допустим: L1 сейчас имеет только объяснение, а L2 — supporting evidence из runtime slice; собственный flow последнего `not-started` модуля даёт execution-oriented practice/integration evidence на primary client boundary.

Новый central action различим с принятыми материалами при следующих границах:

- R2/R4/R5 исследуют amplification, deadline, cancellation, pool saturation и recovery; новый пакет не повторяет fan-out и настройку ресурсов;
- S10 исследует правдивую test boundary входного Orders validation/error contract; новый пакет работает с фактическим outbound HTTP response Pricing и переводит transport/protocol result в предметный outcome вызывающего сервиса;
- корректный пустой результат Pricing остаётся business absence, а malformed payload/media type/status, timeout, transport error и 5xx не превращаются в пустой список;
- одна попытка без automatic retry допустима для read-only L1/L2 slice только как явное решение после B5 applicability, а не как универсальная retry policy;
- A3 readiness ограничивается доверенным адресом dependency и отсутствием произвольного пользовательского target; SSRF остаётся отдельным S14 package.

Есть одно planning-уточнение O-1: канонический S08 формулирует fan-out/slow-dependency failure, уже покрытый runtime slice. Новый пакет использует тот же Quote/Pricing контекст для другого аспекта primary capability, но не вправе заявлять, что response interpretation повторно или полностью «закрывает S08». Это уточняется до acceptance без смены выбора.
