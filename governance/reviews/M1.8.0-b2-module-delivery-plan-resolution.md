## Решение C-3: каноническая формулировка artifact set

П. 5 «Минимального artifact set» приводится к виду: «одна компактная project specification с одним milestone, добавляющим наблюдаемый integration result сверх kata; если такого результата нет — сузить или изменить milestone, а не дублировать практику». Слово «или» между project specification и milestone убирается: жанр project-spec обязателен (прецедент обоих принятых slices), сокращённым может быть только его объём. Формулировка раздела рисков («Project specification остаётся обязательной частью end-to-end flow») становится единственной нормой.

## Решение C-2: судьба пункта о статусе runtime slice

Пункт исключается из «Рекомендуемого scope независимого review» как ссылающийся на несуществующее расхождение. Единственная реальная особенность — R1 принадлежит модулю `b2.module.http-service-runtime` при slice-README у `b2.module.performance-resource-control` — уже корректно зафиксирована в реестре артефактов плана (primary module R1 = HTTP service runtime) и используется как основание состояния `partial`; после правки C-4 дополнительной формулировки не требуется.
