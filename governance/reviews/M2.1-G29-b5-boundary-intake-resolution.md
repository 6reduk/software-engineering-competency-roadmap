# M2.1 — решение оркестратора по G29

## Решение

B5 boundary intake содержательно пригоден для последующего breadth-pass. Оба
профиля независимо подтвердили границы, prerequisites, три screening-кандидата,
C1-носитель и фазовые ограничители. Альтернативный intake или изменение направления
не требуется.

Сам intake пока остаётся `review`. До acceptance выполняется один correction-pass
по `governance/work-packages/M2.1a-G29-findings-correction.md`.

## Disposition

| Finding | Решение |
|---|---|
| C-1 major | Исправить до acceptance: добавить уникальный `id: b5.plan.boundary-intake`, обновить дату и проверить отсутствие коллизии без изменения содержания |
| C-2 note | Перенести обязательным guardrail в будущий breadth-pass: модели и trade-offs без реализации consensus/replication protocols или production topology |
| C-3 note | Перенести обязательным результатом будущего breadth-pass: ограниченная таксономия типов системных решений для решения о втором slice |
| C-4 note | Перенести обязательной boundary-оговоркой будущего blueprint: store-specific replication остаётся B3, системная гарантия и размещение — B5 |
| C-5 note | Исправляет оркестратор в acceptance/governance-pass, не автор M2.1a |

## Граница correction

M2.1a меняет только front matter `governance/planning/intakes/b5-boundary-intake.md`. Он не
переписывает содержание, не исправляет selection, не создаёт blueprint, semantic
entities, coverage, Gate 0 или учебные материалы и не запускает повторный G29.

После handoff оркестратор выполняет точечную проверку C-1. Только отдельный
acceptance-pass может принять intake, исправить lifecycle-фразу selection и
разрешить подготовку bounded breadth-pass.
