# M1.8.1 — решение оркестратора по G5 Service Architecture/S06

Консолидированный verdict `accepted_with_changes` принят: `0 blocker / 0 major / 1 minor / 2 note`. Архитектурная корректность, progression L1–L3, coverage, human readability, различие kata/project и выполнение C-5/C-6 подтверждены двумя независимыми профилями.

## Решения

- **C-1, minor — закрыт:** retry исключён из списка будущих тем. README теперь прямо говорит, что downstream retry уже раскрыт в принятом runtime-материале.
- **C-2, note — закрыт:** подсказка kata больше не просит повторно составлять уже выданную таблицу; она фокусирует участника на вычислении решения обычным Python-вызовом без session/client.
- **C-3, note — принято ограничение среды:** рабочего Git repository нет, поэтому Ownership подтверждён файловыми и семантическими проверками. При появлении корректного repository проверку можно повторить через `git diff`, но пакет это не блокирует.
- **E-1, оркестраторский erratum — закрыт:** в `coverage-map.md` ошибочная ссылка «M1.5 проверяет metadata/registration contract» исправлена на M1.8.1.

## Граница решения

Принят slice и его coverage, но не весь `b2.module.service-architecture`. Module state и следующий кандидат пересчитываются отдельным обновлением `module-delivery-plan.md`; наличие полного artifact flow не превращается автоматически в module-gate decision.

Полный повтор G5 не требуется: изменения локальны, не меняют semantic IDs, coverage relationships, S06 substrate или evidence contract.
