# M1.9.5 — решение оркестратора по G26

## Решение

Консолидированный результат принят как `accepted_with_changes`: **0 blocker / 1 major / 2 minor / 4 note**.

Два независимых профиля подтверждают техническую модель, Gate 0, учебную ценность, границы L1–L3 и пересчёт coverage SE01. Пять материалов пока не принимаются: служебный probe и три JSON-журнала занимают около 97,5% authoring work package, ухудшают zoom-навигацию и открывают готовую оснастку из ссылки coverage map. До acceptance evidence нужно вынести в отдельные служебные sidecar-файлы без потери исходных байтов и SHA-256.

Один ограниченный correction-pass по [`M1.9.5a-G26-findings-correction.md`](../work-packages/M1.9.5a-G26-findings-correction.md) закрывает C-1–C-3. Повторный полный G26 и новые независимые профили не нужны: оркестратор проверит mapping, хэши, ссылки, уменьшение work package и сохранность технических/coverage-инвариантов.

## Disposition findings

| Finding | Решение | Обоснование |
|---|---|---|
| C-1, major | Исправить до acceptance | Достоверность evidence подтверждена, но его форма нарушает zoom-модель и смешивает человеческий Gate 0 с 12 тысячами строк машинного журнала. Перенос четырёх файлов сохраняет воспроизводимость и убирает готовую оснастку из основного маршрута. |
| C-2, minor | Исправить в том же проходе | Несколько терминов не объяснены при первом употреблении в автономных материалах. Нужны локальные человеческие пояснения, а не общий словарь или массовый перевод. |
| C-3, minor | Исправить в том же проходе | `curriculum/tracks/b3/README.md` получил SE01 2026-09-13, но metadata осталась 2026-09-11. |
| C-4, note | Backlog / no change | Автономность материалов оправдывает повтор договора; сокращение финальных source-блоков не требуется для acceptance. |
| C-5, note | No change | Defect намеренно останавливается до validation; это честно отражено. |
| C-6, note | No change | Заданная lock-пара допустима для L2 kata; самостоятельный выбор остаётся в project-spec. |
| C-7, note | Принять фиксацию consolidated | L2 project-spec не считается вторым независимым подтверждением того же L2 результата kata. L3 требует собственного сравнения и не наследуется. Изменение coverage не требуется. |

## Сохраняемые инварианты

- Gate 0 остаётся `confirmed`, work package — `ready`, пять материалов и coverage map — `review`;
- технические результаты, версии, image locator, commands, claims, thresholds, fixtures, oracle, Control/Defect/Fixed и cleanup не меняются;
- четыре evidence-файла после переноса должны побайтово давать исходные SHA-256;
- в work package остаётся человеческий Gate 0 record и компактный индекс `claim → файл → SHA-256 → byte convention`, но не полные исходники/журналы;
- пять материалов остаются автономными и не получают ссылок на служебный probe либо журналы;
- coverage остаётся 30 отношений SE01 к восьми targets с ролями `2/6/6/4/8/4`; accepted totals SQ01 остаются 30;
- L4/L5, B2/B6/B7, production readiness, proficiency, ImplementationReference и module completion не добавляются;
- BR01, новый deep slice и program/module acceptance не запускаются.

## Acceptance boundary

После handoff M1.9.5a оркестратор выполняет точечную проверку C-1–C-3 и инвариантов. Только отдельный acceptance-pass может перевести пять материалов, coverage map и связанные work packages/review artifacts в `accepted`. Correction не является learner implementation, production migration или завершением B3.
