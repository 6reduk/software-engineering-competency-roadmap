## Консолидированные findings

Источник: 🔵 — GLM (профиль A); 🟡 — Kimi (профиль B). Полные evidence и рекомендации — в исходных review; здесь сжатая запись с диспозицией.

### Minor

**C-1 (🔵 GLM F1). Learn: подпись «Обещанный ответ:» стоит перед JSON-блоком запроса.**
В разделе «Один контракт, один дефект» метка ответа прикреплена к ближайшему блоку — телу запроса; статус-строка и Problem Details идут следом. Learn — единственный файл slice с такой подачей (в README, interview, kata и project-spec вводные однозначны). В точке задания канонического substrate читатель вынужден перечитывать, разделяя запрос и ответ.
Диспозиция: **fix-проход** — заменить вводное предложение перед JSON запроса на «Точный invalid request:» (или переместить блок запроса до фразы об обещанном ответе). Однострочная правка.

**C-2 (🟡 Kimi F-1). Роль заголовка `Accept` нигде явно не объяснена.**
`Accept: application/problem+json` — элемент substrate, но ни один файл не сообщает, что это заданный контракт приложения, а не механизм content negotiation FastAPI. Runtime (сценарии D1/D2) показал: media type ответа определяется зарегистрированным handler либо default error path и не зависит от `Accept`. Ложного утверждения в материалах нет, однако участник может построить модель «сервер вернул Problem Details, потому что клиент попросил».
Диспозиция: **fix-проход** — одна фраза в learn (раздел «Один контракт, один дефект» или «Четыре границы на одном substrate»): `Accept` здесь — декларация клиентского контракта; FastAPI/Starlette не выполняет content negotiation, media type ответа определяется exception-handler регистрацией. Закрывается в одном проходе с C-1.

### Note

**C-3 (🟡 Kimi F-2). Табличный шортхенд «неверно типизированный handler».**
Строка таблицы четырёх границ менее точна, чем фактическая модель dispatch по exception type, которая корректно дана в kata и interview; runtime-сценарий C подтвердил lookup по классу исключения. На неверный вывод не наводит.
Диспозиция: **fix-проход (опционально)** — при правке той же таблицы заменить на «отсутствующий или зарегистрированный для другого exception type handler»; допустим backlog.

**C-4 (🔵 GLM F2). «Composition root» без глосса при первом употреблении в learn.**
Определение есть только в принятом S06-материале по ссылке; внутри slice глосс появляется позже и в kata.
Диспозиция: **fix-проход (опционально)** — «точка сборки приложения (`composition root`)» при первом употреблении.

**C-5 (🔵 GLM F3). Терминологическая консистентность slice.**
Синонимия «проверка»/«check»; ячейка «стоимость зависит от способа запуска consumer/provider» без уточнения объектов; «fault cards» в project-spec до словаря и без словарной статьи. Понимание не ломается.
Диспозиция: **backlog / следующий editorial-проход** — выбрать одно обозначение для «проверка/check» в связном тексте, уточнить ячейку про consumer/provider, добавить «fault card» в словарь project-spec.

**C-6 (🔵 GLM F4). README: трассировочная фраза «Compatibility L1» без разрешающейся ссылки.**
Человеческая формулировка присутствует, полные ID есть в coverage-map.
Диспозиция: **fix-проход (опционально)** — добавить ссылку на раздел level-outcomes.md либо оставить только человеческую формулировку.

**C-7 (🔵 GLM F5). Interview: ожидаемый ответ на follow-up 8 — плотное slash-перечисление.**
Остальной interview связный; ответ — резюме после развёрнутого объяснения в learn.
Диспозиция: **fix-проход (опционально)** — одно вводное предложение обычным языком перед перечнем контрольных точек.

**C-8 (🟡 Kimi F-3). Транспорт TestClient на закреплённом baseline уже deprecated.**
`starlette.testclient` через httpx печатает deprecation warning (httpx2); на заявленное поведение не влияет, все сценарии прошли.
Диспозиция: **зафиксировать до следующего обновления baseline** — при смене версий дополнительно закрепить версию тестового транспорта (httpx/httpx2) в `versions`.
