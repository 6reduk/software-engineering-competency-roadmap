## Предварительная техническая сверка

- FastAPI 0.141.1, Starlette 1.3.1, PyJWT 2.13.0 и `cryptography` 50.0.0 существуют в официальных release registries на дату Gate 0.
- Metadata FastAPI 0.141.1 объявляет `starlette>=0.46.0` без верхней границы; pinned Starlette 1.3.1 удовлетворяет этому constraint.
- Starlette 1.6.0 новее закреплённой 1.3.1. Материалы честно называют upgrade debt, но не объясняют, почему для нового slice выбран не latest compatible release. G9 обязан проверить точный pinned-набор runtime и adjudicate: сохранить 1.3.1 с воспроизводимым основанием либо обновить весь slice согласованно.
- PyJWT API подтверждает fixed allowed algorithms и предупреждает не выводить `algorithms` из attacker-controlled token header; Gate 0 следует этому правилу.
- PyJWT `require` проверяет наличие claims, но не их содержательную валидность; материалы отдельно требуют type/non-empty checks для `sub` и `tenant_id`, а issuer/audience/time validation должна быть подтверждена runtime.
- RFC 9110 допускает `404` вместо `403`, если сервер скрывает существование forbidden resource; выбранная модель является локальным контрактом, а не универсальным HTTP-требованием.

## Риски, переданные G9

1. Воспроизвести exact dependency set, JWT validation и пять populations на собранном ASGI/HTTP path.
2. Проверить missing/malformed/invalid bearer challenge по RFC 6750, включая отсутствие лишнего `error` при отсутствии authentication information.
3. Проверить полное wire-равенство cross-tenant/missing contract в заявленной области и не подменять его обещанием отсутствия всех timing/side-channel различий.
4. Проверить, что внутреннее различение audit reasons не становится внешним disclosure channel и что credentials/secrets отсутствуют.
5. Проверить правдивость L3: несколько реальных bypass paths и application-level enforcement, а не одна HTTP-проверка с L3-ярлыком.

## Решение intake

Gate 0 считается достаточно конкретным для запуска независимого G9. Runtime-воспроизведение оркестратор на intake не подменяет: его выполняет technical reviewer на точном substrate. Program gate и statuses материалов не изменяются.
