# M1.9.4 — принятие schema-evolution intake SE01

## Итог

M1.9.4 и gate G25 приняты с verdict `accepted` после двух независимых профилей, консолидации и correction-pass M1.9.4a:

- исходный verdict — `0 blocker / 1 major / 4 minor / 3 note`;
- C-1–C-6 закрыты в одном planning artifact без изменения выбранного действия;
- C-7/C-8 сохранены обязательными неподтверждёнными решениями будущего Gate 0, а не объявлены закрытой технической readiness;
- выбрано одно store-level действие: совместимый переход `orders.amount_rub numeric(12,2)` → `amount_minor bigint` через дополнительный столбец, сосуществование двух версий и backfill;
- B2/B3/B6/B7 ownership сохранён, BR01 не запущен;
- Gate 0, runtime evidence, учебные материалы, coverage, learner implementation и ImplementationReference не создавались.

## Verification-pass M1.9.4a

- Defect теперь требует двух различимых шагов: захватить 10000 до барьера и попытаться применить именно это сохранённое значение после подтверждённого W-old на 12000.
- До полного опыта будущий Gate 0 обязан закрепить isolation level backfill/W-old, ожидаемую сигнатуру Defect и воспроизвести её короткой пробой. Одношаговый `UPDATE`, молча совпавший с Fixed, не считается доказательством.
- Авторитетным названо последнее подтверждённое изменение суммы через W-old/W-new; backfill остаётся неавторитетной технической копией.
- Topology и readiness согласованы на шести соединениях, включая отдельный writer-сеанс lock-пробы; совмещение ролей требует обоснования.
- `NOT_RUN` заменён человеческим статусом, Gate 0 объяснён при первом употреблении; `validation`, `fixtures`, `readers/writers`, `probe` и `scaffold` получили локальные объяснения.
- Пятое состояние честно называется завершением опыта с обязательным новым и сохранённым старым представлением.
- Границы входных сумм и порядок включения механизма совместимости/enforcement явно оставлены неподтверждёнными входами Gate 0.

Точечная проверка подтвердила metadata, отсутствие поля `coverage`, шесть строк oracle, пять состояний и 17 разрешающихся локальных ссылок. Conflict markers и trailing whitespace отсутствуют; файл завершается переводом строки. Авторский SHA-256 snapshot подтверждает только границы correction-pass и не используется как историческое Git-доказательство.

## Граница принятия

Acceptance подтверждает пригодность intake как постановки следующего технически зависимого zoom. Она не подтверждает конкретную PostgreSQL/Psycopg сборку, DDL/lock semantics, достижимость 2/60 секунд, корректность механизма совместимости, runtime evidence, coverage, proficiency, production migration или завершение модуля B3.

Удаление `amount_rub`, production cutover и реальный adoption остаются за пределами SE01. Будущий лабораторный опыт должен закончиться проверенным новым представлением при сохранённом старом пути.

## Следующий шаг

Выполнить отдельный M1.9.5: сначала подтвердить Gate 0 на закреплённой среде и только затем создать пятижанровый учебный slice SE01. Если хотя бы один обязательный вход readiness не подтверждается либо Defect неотличим от Fixed, authoring не начинается и пакет возвращается оркестратору.
