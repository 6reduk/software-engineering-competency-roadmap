# M1.8.17 — решение оркестратора по G16 External Integration/S08

## Процессуальное решение

По прямому решению владельца программы профиль B временно пропущен из-за недоступности SaaS-подписки. G16 не считается двухпрофильным review, consolidated-артефакт не создаётся, а отсутствие learning/editorial профиля не маскируется под независимую проверку.

Получен один независимый профиль A с verdict `accepted`: `0 blocker / 0 major / 0 minor / 4 note`. Профиль независимо воспроизвёл Gate 0 на идентичном baseline во временном каталоге вне проекта, удалил probe и подтвердил техническую модель, measurement envelope, coverage mechanics и отсутствие scope overclaim.

Область пропущенного профиля B проверена оркестратором только как ограниченный acceptance risk assessment: автономность точек входа, human-readable context, скрываемые ответы, различие kata/project и соответствие редакционному стандарту. Это не объявляется вторым независимым review.

Итоговое решение: `accepted`. Correction package не требуется; четыре notes принимаются как явно ограниченные свойства evidence. Однопрофильное исключение относится только к G16 и не отменяет базовый двухпрофильный процесс для следующих gates.

## Подтверждённая техническая модель

- Фактический outbound путь проходит через loopback HTTP Pricing, HTTPX client adapter и FastAPI Quote, а не через готовый mock result.
- Матрица содержит два допустимых результата и девять failure rows; после исправления только валидный `200 application` JSON с `offers=[]` даёт `no_offers`.
- Порядок `status → media type → decoding → schema/identity → domain outcome` подтверждён, включая `503` с похожим на пустой успех телом.
- Арифметика независимо воспроизведена: 82 входящих проверки, 79 client attempts, 79 server receipts, `27/27` ложных отсутствий на defect, `0/27` после исправления и recovery `6/6`.
- One-attempt evidence использует раздельные client/server observations, `retries=0`, отключённые redirects и отсутствие application retry loop/auth resend.
- Timeout не выдан за remote cancellation: независимый probe наблюдал последующий drain около 250 мс.
- Все локальные response/drain/cleanup thresholds выполнены; они не объявлены production SLO.
- Trusted authority проверена как readiness выбранной конфигурации, но не выдана за полноценную SSRF protection.
- Pinned и current stable версии, strict Pydantic behavior и source-to-claim mapping подтверждены профилем A.

## Оркестраторская learning/editorial risk assessment

- README вводит рабочую историю и объясняет central distinction до IDs и coverage notation.
- Learn строит причинную цепочку от полученного HTTP response к допустимому предметному выводу, а не только перечисляет коды ошибок.
- Interview содержит L1 application questions и L2 design questions с раскрываемыми ориентирами ответа.
- Kata ограничена одним заданным failure→empty defect, известной матрицей и L1 execution evidence; scaffold и готового адаптера нет.
- Project требует самостоятельного выбора внутренних result/error types, mapping boundary, resource owner и one-attempt decision; это отдельное L2 integration evidence.
- Термины объясняются при первом употреблении и локальными словарями; англоязычные рабочие термины не заменяют русский контекст.
- Подробный measurement envelope повторяется в learn, kata и project, но выполняет разные функции: объяснение доказательства, обязательный протокол исправления и критерий самостоятельного проекта. Повторение заметно, однако не делает жанры взаимозаменяемыми.

## Disposition notes

| Finding | Решение | Обоснование |
|---|---|---|
| A-N-1 — точные timing отличаются | Принять без правки | Независимые значения находятся в тех же границах; материалы называют авторские числа ориентиром и требуют собственных измерений участника. |
| A-N-2 — release responses подтверждён косвенно | Принять как предел evidence | Чистые client close, отсутствие незавершённой работы и закрытие port/thread достаточны для bounded Gate 0; post-row pool instrumentation относится к будущему расширению. |
| A-N-3 — нет connect-refused в основной матрице | Принять без расширения | Текущий transport row намеренно получает server receipt до socket close; connect-refused уже честно описан как иной случай и может быть отдельным edge check. |
| A-N-4 — substitutions независимого probe | Принять и сохранить в audit trail | Substitutions раскрыты, baseline совпал, семантика дефекта и failure injection не изменилась, временный probe удалён. |

## Условия acceptance

Условия выполнены без correction package:

- нет открытых blocker, major или minor;
- Gate 0 независимо подтверждён в заявленных границах;
- пять materials имеют единый контракт и различимые External L1/L2 evidence;
- YAML содержит ровно 9 relationships к трём targets с ролями `1 reference / 2 explain / 2 probe / 1 practice / 2 assess / 1 integrate`;
- External L3/L4, A3/B5 и supporting coverage отсутствуют;
- готовой реализации, scaffold и ImplementationReference нет;
- принятие slice не является module-gate decision и не означает completion всего канонического S08.
