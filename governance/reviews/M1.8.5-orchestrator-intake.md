# M1.8.5 — orchestrator intake

## Verdict

`changes_required` до запуска G7: `0 blocker / 1 major / 0 minor / 0 note`.

Структура пакета, Ownership, регистрации, заявленное coverage и раздельное evidence для Transaction L3 и Idempotency L3 прошли intake. Транзакционные утверждения о `READ COMMITTED`, Psycopg transaction context, локальной durability и неизвестном исходе `COMMIT` согласуются с указанными первичными источниками.

## I-01 — major — неверная текущая minor-версия PostgreSQL

**Факт.** На дату проверки 2026-08-21 официальный PostgreSQL versioning registry указывает `18.6` как current minor для PostgreSQL 18. Выпуск опубликован 2026-08-13. В Gate 0 и пяти материалах закреплён `18.4`, причём он назван текущим стабильным выпуском.

**Источник.** [PostgreSQL Versioning Policy](https://www.postgresql.org/support/versioning/) — проверено 2026-08-21.

**Влияние.** Gate 0 нельзя считать подтверждённым при фактически неверном freshness assertion; одинаковая ошибка размножена в metadata и основном тексте всех пяти материалов.

**Требуемое исправление.** Выполнить узкий пакет [M1.8.5a](../work-packages/M1.8.5a-postgresql-version-correction.md). После него нужен только orchestrator verification-pass; независимый G7 ещё не запускать.

## Проверено без замечаний

- Psycopg `3.3.4` обозначен официальной документацией как current release; `3.3.5` ещё unreleased.
- `autocommit=True` вместе с внешним `with conn.transaction():` создаёт явную transaction boundary; на не-autocommit connection вложенный context мог бы управлять только savepoint.
- При `READ COMMITTED` конкурирующий `UPDATE` ждёт завершения первого updater и повторно проверяет `WHERE` на актуальной версии строки.
- При `fsync=on` и `synchronous_commit=on` успешный локальный commit ждёт локального WAL flush; это не доказывает публикацию во внешний sink.
- `transaction_status=UNKNOWN` описывает bad connection и не раскрывает durable outcome уже отправленного `COMMIT`.
