# M1.4 — G3 review B2 pilot blueprint

## Scope

- `curriculum/tracks/b2/README.md`;
- modules, capabilities и LevelOutcomes;
- internal/external prerequisites;
- рабочие/interview scenarios;
- preliminary capability/outcome coverage;
- B2 detail первых двух RoleView.

## Reviewers

- Domain reviewer — техническая полнота, ownership и корректность backend/API модели.
- Learning/level reviewer — наблюдаемость capabilities, progression/evidence, bounded modules, role requirements и coverage semantics.

Reviewers не редактировали пакет. После adjudication и исправлений оба выполнили узкий re-pass.

## Существенные findings и решения

| Severity | Finding | Решение |
|---|---|---|
| Major | Три hard edges не были универсально обязательными | Resource tracing, idempotency для всех workflows и external dependency для cancellation перенесены в `related`; hard DAG сохранён ацикличным |
| Major | Не было B2-owned API security/abuse enforcement | Добавлена capability с L1–L4, S14, coverage и границами A3/B6/B7 |
| Major | Выпало application caching | Добавлена integration capability с L2–L4, S15 и conditional B3 dependency |
| Major | Architecture RoleView фактически требовал почти весь B2 на L4 | Установлен L3 baseline, 5 обязательных интегрирующих L4 и exact-ID conditional specializations |
| Major | Coverage существовал только на capability level | Для двух slices добавлены exact LevelOutcome targets и coverage roles; interview не объявлен доказательством L4 execution |
| Medium | Aggregate catalog notation не была формализована | Определены governance status, defaults, обязательные row fields и materialization rule без смены IDs |
| Medium | L4 evidence могло подтверждаться одним policy-документом | Введён обязательный multi-team adoption/migration и feedback-loop guardrail |
| Medium | Два modules были слишком широки | External integration отделён от background workflows; verification — от safe evolution; итог 10 modules |
| Medium | B1 async baseline блокировал нерелевантные modules | Общий Python baseline отделён от conditional async/concurrency dependency |
| Minor | Cleanup, reversibility и performance evidence были слишком абсолютны | Уточнены controllable boundaries, compensation/roll-forward и измеримый workload/failure envelope |
