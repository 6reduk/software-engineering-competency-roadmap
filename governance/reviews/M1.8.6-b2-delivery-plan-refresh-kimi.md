## Вывод по S09, B5 readiness и границам consumer workflow

1. **S09 — следующий лучший bounded package, выбор менять не следует.** Capability — root в internal DAG; обе RoleViews требуют Workflow L3 при полностью пустых Workflow L2–L4; пакет открывает первый собственный flow not-started модуля и переиспользует принятый S07 substrate (event identity, idempotency) и R1 cancellation context без дублирующих relationships. Сильнейшие альтернативы объективно слабее по readiness: S05/S14 зависят от неподтверждённого A3 security baseline, способного изменить enforcement model; S15 требует нового B3 cache-store substrate и расширяет уже partial module. Это не предпочтение порядка тем, а разница в readiness и новом уникальном coverage.

2. **Минимальный B5/broker readiness contract до authoring:** gating-раздел внутри будущего S09 authoring package (паттерн D-046), фиксирующий до первого учебного artifact: (а) применимый B5 language baseline, ограниченный ack/nack, redelivery, bounded retry, poison path и partial failure, со ссылками на первичные источники; (б) ровно один broker/adapter substrate с документированной конкретной ack/redelivery семантикой; (в) явное заявление, что это conditional advanced context — не hard DAG edge, без placeholder capability IDs; (г) подтверждённую воспроизводимость crash window after-side-effect-before-ack и наблюдаемой redelivery. При неподтверждении семантики первичными источниками пакет остаётся выбранным, но authoring не запускается.

3. **Сужение обязательной семантики S09:** обязательны ровно критерии evidence Workflow L2/L3 — определённая ack/retry/error ownership граница, проверенные duplicate и poison path (L2), наблюдаемые state transitions/invariants и replay/recovery, не нарушающие бизнес-результат (L3). Всё остальное остаётся non-goal: exactly-once, универсальный inbox/dedup recipe, broker internals, обзор delivery guarantees, DLQ-curriculum, второй workflow, lifecycle/shutdown как самостоятельная тема. Kata держит один seeded crash window; project ограничен несколькими fault points одного и того же consumer workflow.

4. **S09 authoring work package можно создавать после disposition findings; отдельный prerequisite package не требуется.** Прецедент D-046 (gating-раздел внутри authoring package для B3/S07) принят и успешно применён в M1.8.5; масштаб B5-зависимости тот же — conditional advanced context, а не отсутствующий hard prerequisite. Условие: authoring package обязан начинаться с readiness-gate раздела по контракту пункта 2 и вернуть выбор оркестратору, если варианты broker/adapter дают существенно разные учебные результаты.
