После дедупликации OpenAPI freshness являлся одним finding. Два замечания о якобы отсутствующей coverage role `probe` были сняты как фактическая ошибка reviewer-ов: `probe` уже определён в `governance/architecture/metamodel/relationships-and-invariants.md`, `metadata.md` и D-035; замена на `assess` нарушила бы принятую semantics evidence.

## Внесённые изменения

1. OpenAPI baseline разведен на OAS 3.1.2 как нормативный baseline линии 3.1, latest OAS 3.2.0 и documented FastAPI output 3.1.0; добавлены version metadata и актуальные первичные ссылки.
2. Request execution model заменена с линейной на normal/exception/cleanup branches с явной response-start boundary.
3. Interview metadata дополнена `b2.level-outcome.verify-contract-compatibility-l3-build-consumer-evidence` с ролью `probe`.
4. Negotiated legacy/new representations требуют согласовать signal, media type и cache variance через `Vary` либо обоснованный запрет shared caching.
5. RFC 9457 checklist дополнен stable absolute type URI, title, intended status, совпадением body/wire status и решением о документации URI.
6. Добавлена caller/provider compatibility matrix, устраняющая неоднозначность request/response producer/consumer.
