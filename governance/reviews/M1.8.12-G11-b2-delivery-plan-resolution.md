# M1.8.12 — решение оркестратора по G11 review B2 delivery plan

## Решение

Консолидированный verdict `accepted_with_changes` принят: `0 blocker / 0 major / 2 minor / 3 note`.

G11 независимо подтвердил механический аудит: 42 accepted artifacts, 216 relationships (`18 capability-level + 198 outcome-level`), 55/69 covered, 14 uncovered, 7 probe-only и состояния модулей `0 complete / 8 partial / 2 not-started / 0 blocked`. Hard DAG не изменился.

Выбор Application Caching/S15 следующим bounded package принят по существу. План правдиво ограничивает новое coverage уровнями Cache L2/L3, не заявляет Cache L4 и не начисляет supporting capabilities. Более сильного кандидата среди callback/SSRF, HTTP Runtime и External Integration сейчас нет.

До окончательного acceptance требуется один локальный correction-pass по [`M1.8.12a-delivery-plan-findings-correction.md`](../work-packages/M1.8.12a-delivery-plan-findings-correction.md). Повторный полный G11 не нужен: достаточно orchestrator verification по C-1–C-5 и неизменности инвариантов.

## Уточнённый readiness contract S15

До первого учебного artifact Gate 0 будущего authoring package обязан закрепить:

- выбранные cache store и client с версиями и первичными источниками;
- source of truth и один tenant-scoped read path;
- tenant-safe cache key и правила его построения;
- TTL и проверяемый freshness invariant;
- process/worker topology и границу гарантии request coalescing;
- atomicity/coordination semantics выбранного механизма;
- invalidation ordering относительно commit: до commit, после commit либо versioned keys, включая допустимые исходы race;
- cache failure и fallback behavior;
- populations, counters, measurement points, thresholds и stop conditions.

B5 coordination readiness требуется только тогда, когда заявленная гарантия coalescing выходит за один процесс/инстанс либо зависит от coordination semantics вне обычного контракта выбранного cache store/client. В таком случае B5 используется как дополнительный conditional gate сверх перечисленных в каталоге consumers. Если доказательство ограничено одним процессом, достаточно B3 cache-store readiness и явного ограничения применимости evidence; распределённая гарантия не заявляется.
