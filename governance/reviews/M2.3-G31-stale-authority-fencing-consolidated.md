# M2.3 — G31 консолидированный review stale authority / fencing

## Назначение

Отчёт объединяет два независимых профиля G31 и перепроверяет их findings по пяти материалам, coverage map, Gate 0 record и доступным временным evidence-файлам автора. Он не принимает M2.3, не переводит материалы из `review`, не начисляет accepted coverage и не выбирает второй B5 slice.

После correction требуется точечный verification-pass и отдельное решение об acceptance.

## Согласованные выводы

- Технический тезис slice корректен в заявленной границе: новая authority сама не останавливает старую команду; устаревшее поколение должно быть отклонено атомарно в точке эффекта.
- Проверенная гарантия уже сильнее простого выбора B, но уже немедленного запрета A после выдачи `t2`: стенд защищает принятый эффект B от последующей замены A.
- Lease/election не выданы за fencing, часы не используются как порядок authority, safety отделена от progress, а trusted-worker bypass честно оставлен непроверенным.
- Временные `gate0.py` и `evidence.json` существуют; их SHA-256 совпадают с Gate 0 record. В evidence — 30 summaries, 130 событий и 45.257 секунды; fixed-истории содержат принятие B, отклонение A, сохранение B и принятие B-next. Это подтверждает финальную серию, но не исправляет нарушение порядка Gate 0 → authoring.
- Пять жанров различимы: index адресует маршрут, learn объясняет модель, interview проверяет рассуждение, kata даёт одну заданную передачу, project требует собственный механизм, дополнительные истории и защиту решения.
- Coverage пересчитан как 5 artifacts / 11 targets / 35 relationships: `reference 3 / explain 8 / probe 8 / practice 4 / assess 8 / integrate 4`. Supporting leadership ограничен L1/L2; соседние треки, L4/L5, proficiency, module completion и production readiness не начислены.
- Accepted relationships M2.3 остаются равны нулю.

## Расхождение по Gate 0

Первая серия и первоначальная запись Gate 0 действительно предшествовали authoring. Однако она не доказывала, что конкретный payload был сохранён до паузы A. Исправленная оснастка и финальная полная серия 10/10/10 были выполнены после создания материалов. Поэтому формулировки `governance/work-packages/M2.3-stale-authority-fencing-slice.md:55` и `curriculum/tracks/b5/README.md:135` о безусловном подтверждении Gate 0 до создания материалов неверны для финального evidence.

Это не делает технический результат недействительным: дефект обнаружен честной авторской самопроверкой, затем вся серия повторена. Но это нарушение обязательного процесса, а не обычная редакционная оговорка. Severity A-G31-1 сохраняется как **major**. До acceptance требуется точная хронология без ретроспективного объявления финального Gate 0 предварительным.

## Verdict

`accepted_with_changes`: **0 blocker / 1 major / 4 minor / 3 note**.

Техническая и учебная конструкция состоятельна. До acceptance требуется один ограниченный correction-pass C-1–C-5. Повторный полный G31 не нужен.

## Граница следующего шага

M2.3a меняет только Gate 0 work package, B5 README и пять материалов slice. Coverage map, semantic IDs, relationships, техническая модель, версии, результаты 10/10/10 и статусы материалов не меняются. Автор не повторяет G31 и не объявляет acceptance.
