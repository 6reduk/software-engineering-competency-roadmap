## Вывод по числам и state transitions

Воспроизводимый алгоритм: (1) обойти все 22 `.md` в `curriculum/tracks/b2/slices/**`, распарсить YAML frontmatter (`pyyaml`), собрать `(artifact, target, role)`; (2) канонические 69 ID извлечь из `level-outcomes.md`; (3) считать relationship один раз на YAML-запись, capability-level отдельно от outcome-level; (4) covered = outcome с ≥1 связью, probe-only = множество ролей строго `{probe}`; (5) membership модулей — из `Develops` `modules.md`, primary — из `capabilities.md`; (6) own-artifacts модуля — по полю `module` YAML.

Результат: **22 / 155 (13+142) / 42 / 27 / 7 probe-only — подтверждены полностью**, равно как и «ожидаемое снижение probe-only до шести не подтвердилось»: Verification L3 вне этого множества со времён R5, Compatibility L1 вошёл сразу с `explain`/`practice`/`assess`. Реестр, 69 строк аудита, membership-числа и shared membership синхронны с каталогами и YAML без единого расхождения. Переход состояний ровно один — Service Verification `not-started → partial`; `complete` не появился ни у одного модуля, включая четыре с полным набором жанров; D-044 применён корректно.

## Вывод по S07 и внешнему B3 prerequisite

По структурным критериям профиля A: S07-package ограничен одним центральным действием (одна Orders operation, failure windows, recovery/idempotency invariant), пять заявленных outcome candidates действительно пусты в текущем snapshot, S15 корректно исключён как отдельное центральное действие, повторное использование S04/S06/S10 оформлено ссылками без зачисления coverage за упоминание, non-goals явно отсекают B3/B5 theory и невыполнимые обещания (exactly-once, универсальный outbox, transaction через произвольный network I/O). Минимально достаточный проверяемый артефакт B3 readiness, по мнению reviewer: короткий prerequisite-baseline record (не slice и не расширение scope), фиксирующий (1) выбранный driver/store и закреплённые версии; (2) семантику transaction demarcation begin/commit/rollback, включая поведение при ошибке и неизвестном исходе; (3) применимые isolation assumptions для одной Orders operation; (4) retry-поведение driver при unknown outcome. Проверяемость — ссылки на документацию закреплённой версии и короткие утверждения, которые authoring S07 обязан соблюдать. Место и форма записи выбирает оркестратор; reviewer их не создаёт.
