`accepted_for_review`: `0 blocker / 0 major / 0 minor / 4 note`.

## Проверенный результат

- Gate 0 заполнен в разрешённом разделе work package и помечен `confirmed` до создания материалов. Work package сохранил `status: ready`.
- Созданы ровно пять учебных материалов и первая B3 coverage map; B3 README содержит только навигацию к карте и регистрацию SQ01. Все шесть новых файлов имеют `status: review`.
- Маршрут содержит самостоятельные точки входа index, learn, interview, kata и project-spec вокруг одного дефекта: два независимых отношения «один-ко-многим» размножают строки до агрегирования.
- Канонический договор един во всех жанрах: четыре заказа, суммы в целых minor units, одна итоговая строка на заказ, нулевые показатели для отсутствующих дочерних записей, `balance = line_total - paid_total`, общий ранг равных итогов и отдельный стабильный порядок выдачи.
- Gate 0 различает control, defect и fixed, сверяет полные строки с независимо рассчитанной таблицей и сохраняет три чистых успешных прогона. Технический fixed SQL находится только в служебном evidence work package; в пяти учебных материалах готового исправленного запроса нет.
- Kata задаёт схему, fixtures, дефект и ожидаемый договор, но требует самостоятельно написать исправление и оснастку. Project-spec требует отдельный репозиторий, собственную структуру SQL и проверок, расширенные данные, две трактовки неоднозначного требования и decision record.
- Границы выдержаны: query plans, индексы, общая схема, ORM/API, аналитический pipeline, transaction isolation, SE01/BR01, L4/L5 и production readiness не заявлены.

## Независимая техническая сверка intake

На 2026-09-10 официальная таблица PostgreSQL указывает 18.6 как текущую minor-версию поддерживаемой ветки 18. Документация PostgreSQL 18 подтверждает используемые свойства: `COUNT(*)` считает строки, `COUNT(expression)` — ненулевые значения, `SUM` пустого входа возвращает `NULL`; `dense_rank` не оставляет пропусков, а строки с равными выражениями оконного `ORDER BY` являются peers. Оконная функция сохраняет строки входа и не исправляет ошибочную гранулярность сама по себе.

Первичные источники:

- [PostgreSQL versioning policy](https://www.postgresql.org/support/versioning/);
- [table expressions](https://www.postgresql.org/docs/18/queries-table-expressions.html);
- [aggregate functions](https://www.postgresql.org/docs/18/functions-aggregate.html);
- [window functions](https://www.postgresql.org/docs/18/functions-window.html);
- [sorting rows](https://www.postgresql.org/docs/18/queries-order.html).

Intake не повторял Docker/psql experiment и не подтверждает заявленный digest либо историческую чистоту workspace. Эти ограничения не блокируют review: воспроизводимые схема, запросы, ожидаемые строки и наблюдения сохранены в Gate 0 record.

## Notes intake

### I-1 — отдельно решить правдивость L3 для grouped/window capability

Project-spec требует самостоятельно локализовать искажение, сравнить классы композиции и защитить порядок вычислений. Это выглядит достаточным кандидатом для L3, но G24 должен проверить, не сводится ли фактическая неопределённость только к семантике фильтра из capability составления запросов, оставляя grouped/window L3 повторением L2.

### I-2 — проверить реальную дистанцию между kata и project-spec

Проект расширяет данные, оснастку и предметное решение, однако наследует тот же канонический defect и expected table. G24 должен определить, достаточно ли самостоятельных решений и интеграционного результата для `integrate/assess` L3 либо часть критериев лишь повторяет kata большим объёмом.

### I-3 — проверить автономность без избыточного повторения

Полный договор и источники повторены во всех пяти точках входа, что помогает самостоятельному чтению, но увеличивает объём и риск будущего рассогласования. Методический профиль должен оценить, где повторение необходимо для standalone-материала, а где можно сохранить человеческий контекст более компактно без обязательного перехода по ссылкам.

### I-4 — проверить доступность языка для работающего инженера

Основные термины объяснены локально, ответы скрыты в `<details>`, а текст связан рабочей историей. Тем не менее остаются англицизмы `grain`, `fan-out`, `peers`, `oracle`, `fixtures`, `decision record` и `scaffold`. G24 должен проверить первое употребление каждого термина и предложить правку только там, где русский контекст или словарь действительно недостаточны.
