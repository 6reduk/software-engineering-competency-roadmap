**C-1 (🟡 Kimi F-1). Decision brief приписывает S02 несуществующий принятый cancellation/cleanup flow.**

На выбор S09 и состояния не влияет — опора (R1) названа явно.
Диспозиция: **fix-проход** — заменить на «принятый cancellation/cleanup context R1 (slice S08)» с пометкой, что собственный S02 flow отсутствует.

### Note

## Согласованный вывод по S09, B5 readiness и границам consumer workflow

**S09 — следующий лучший bounded package; выбор подтверждён обоими профилями независимо.** `design-asynchronous-workflows` — root без скрытых hard edges; Workflow L3 обязателен обеим RoleViews при полностью пустых Workflow L2–L4; пакет открывает первый собственный flow not-started модуля и переиспользует принятый S07 substrate (event identity, Idempotency L2/L3) и R1 cancellation context без дублирующих relationships; producer-side outbox S07 исключён. Альтернативы объективно слабее по readiness: S05/S14 — неподтверждённый A3 baseline, способный изменить enforcement model; S15 — новый B3 cache-store substrate и расширение уже partial module. Это разница в readiness и новом уникальном coverage, а не предпочтение порядка тем.

**Минимальный B5/broker readiness contract до authoring** (оба профиля сошлись на одной форме; закрепляется как gating-раздел внутри S09 authoring work package по прецеденту D-046/B3-S07, не отдельный prerequisite package, не hard DAG edge, без placeholder capability IDs):

1. применимый B5 language baseline, ограниченный ack/negative acknowledgement, redelivery, bounded retry, poison path и partial failure, со ссылками на первичные источники (`b5.cluster.messaging-events`, `b5.cluster.idempotency-retries` как owner-track context, не преподаваемый материал);
2. ровно один broker/adapter substrate с документированной конкретной ack/redelivery семантикой (закрытие C-7);
3. явное заявление conditional-advanced-статуса: условие authoring, не внутренняя B2 DAG edge;
4. подтверждённая воспроизводимость crash window after-side-effect-before-ack и наблюдаемой redelivery.

При неподтверждении семантики первичными источниками пакет остаётся выбранным, но authoring не запускается.

**Сужение обязательной семантики S09:** обязательны ровно evidence-критерии Workflow L2/L3 — определённая ack/retry/error ownership, проверенные duplicate и poison path (L2; poison — как ограниченное наблюдение, C-5), наблюдаемые state transitions/invariants и replay/recovery, не нарушающие бизнес-результат (L3). Всё остальное — non-goals: exactly-once, универсальный inbox/dedup recipe, broker internals, обзор delivery guarantees, второй workflow, lifecycle/shutdown как самостоятельная тема, DLQ-curriculum. Kata держит один seeded crash window; project ограничен несколькими fault points того же consumer workflow.

**Ответы на четыре обязательных вопроса профиля B (согласованно):**

1. S09 — действительно следующий лучший bounded package; выбор не меняется.
2. Минимальный readiness contract — четыре пункта выше, форма фиксации — gating-раздел внутри S09 authoring work package.
3. Обязательная семантика сужается до evidence-критериев Workflow L2/L3 (см. выше); остальное — non-goals.
4. После disposition findings создавать S09 authoring work package можно; отдельный prerequisite package не требуется (D-046).
