# M1.8.11 — принятие operation-cost admission/S14 slice

## Итог

M1.8.11 и gate G10 приняты с verdict `accepted`:

- два независимых профиля не нашли blocker или major;
- четыре minor и три локально исправляемых notes закрыты correction-pass C-1–C-7;
- два оставшихся notes получили явные dispositions C-8/C-9 и не являются дефектами текущего slice;
- Gate 0 и exact pinned stack CPython 3.14.0, FastAPI 0.137.1, Starlette 1.3.1 и Pydantic 2.12.5 подтверждены техническим профилем;
- приняты пять artifacts и 13 relationships к четырём semantic targets;
- Abuse L1 проверяет применение заданных strict bounds и обнаружение одного cost bypass до запуска работы;
- Abuse L2 проверяет applicability matrix четырёх категорий, включая честные `not applicable` и residual risks;
- Abuse L3 проверяет server-owned cost model, placement admission, adversarial populations, tenant isolation, сохранность legitimate use и границы synthetic evidence;
- kata остаётся одним L1 bypass, а project добавляет L2/L3 threat/cost matrix, пять populations, audit/error assertions и decision record;
- Abuse L4, Identity/Load Control supporting coverage, aggregate quota/rate, callback/SSRF, production storage и ImplementationReference не заявлены.

## Verification-pass M1.8.11a

C-1–C-7 проверены по пяти материалам:

- объяснён lax-дефолт Pydantic и закреплён syntax-neutral strict contract с negative type cases до cost calculation;
- объяснено дефолтное поведение FastAPI `RequestValidationError`; kata/project требуют собственный безопасный mapper и assembled ASGI/HTTP checks без эха исходного значения;
- `allowlist`, `harness` и `seam` объяснены в месте использования;
- project-spec ссылается на prerequisite S05 человеческим названием и разрешающейся ссылкой;
- recovery ограничен отсутствием накопленного эффекта отклонений и сохранностью следующей допустимой операции;
- обе Mermaid-схемы явно исключают input-invalid и audit paths из своей упрощённой модели;
- второй tenant и минимум 3000 Orders связаны соответственно с isolation evidence и воспроизводимостью populations.

Сохранены пять semantic IDs, 13 relationships, 4 targets и роли `1 reference / 3 explain / 3 probe / 1 practice / 3 assess / 2 integrate`. Версии, endpoint, формула, threshold, populations, counters, fixtures и регистрации не менялись. Повторный независимый G10 не требуется.

## Граница принятия

Acceptance подтверждает только operation-cost половину S14 и gate G10. Она не завершает автоматически `b2.module.identity-aware-boundaries`, не доказывает cross-service Abuse L4 и не превращает лабораторный предел 2000 cells в production default.

C-8 остаётся правилом следующего обновления baseline: при обновлении TestClient stack закрепить фактическую версию `httpx`/`httpx2`. C-9 остаётся governance-ограничением: предзаполненные dispositions applicability matrix допустимы только после package-level adjudication, а участник всё равно создаёт собственные implementation evidence и decision record.

## Следующий шаг

Выполнить M1.8.12: обновить B2 module delivery plan по принятому Abuse L1–L3 coverage, пересчитать artifacts, relationships, covered/uncovered outcomes, probe-only и состояния десяти модулей, затем выбрать один следующий bounded package.
