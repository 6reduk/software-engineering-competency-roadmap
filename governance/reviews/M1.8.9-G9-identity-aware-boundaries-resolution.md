# M1.8.9 — решение оркестратора по G9

## Решение

Содержательный verdict консолидации принят: `accepted_with_changes` — `0 blocker / 0 major / 1 minor / 4 note`. Gate 0, закреплённый runtime substrate, JWT validation model, граница доверенного identity context, object-level authorization, единые `401`/`404`, безопасный audit contract, Identity L1–L3 coverage и различие kata/project подтверждены.

Starlette `1.3.1` сохраняется как воспроизводимый baseline этого slice. Технический профиль воспроизвёл одинаковый набор из 32 проверок на `1.3.1` и `1.6.0`; изменения между версиями не затрагивают проверяемую поверхность S05. Само наличие более новой версии не является основанием для несогласованного обновления одного slice.

Повторный полный G9 после локальных исправлений не требуется. Gate G9 пока не считается пройденным: сначала выполняется пакет [`M1.8.9a-G9-findings-and-review-lineage-correction.md`](../work-packages/M1.8.9a-G9-findings-and-review-lineage-correction.md), затем оркестратор делает точечный verification- и acceptance-pass.

## Дефект аудиторского следа review

Файл `governance/reviews/M1.8.9-G9-identity-aware-boundaries-kimi.md`, изначально предназначенный для независимого профиля B, был заменён консолидированным отчётом. Его metadata теперь имеет `profile: consolidated`, а список `sources` ссылается на этот же путь как на исходный профиль B. Поэтому содержательная консолидация пригодна для adjudication, но структура артефактов нарушает принятую конвенцию и не позволяет отличить исходный профиль B от результата консолидации.

Исправление обязательно до acceptance:

1. сохранить текущую консолидацию под каноническим путём `governance/reviews/M1.8.9-G9-identity-aware-boundaries-consolidated.md` без потери findings, runtime evidence и выводов;
2. восстановить `governance/reviews/M1.8.9-G9-identity-aware-boundaries-kimi.md` как профиль B из явно включённого в текущую консолидацию снимка;
3. честно указать в восстановленном профиле происхождение `restored_from_consolidated`, не заявляя побайтовую идентичность утраченному файлу;
4. удалить самоссылку из `sources` канонической консолидации и сослаться на восстановленный профиль B.

Независимость двух исходных проходов не оспаривается: она зафиксирована обоими отчётами до консолидации. Исправление восстанавливает lineage, но не перепроводит review и не создаёт новое независимое свидетельство.

## Disposition findings

| Finding | Решение | Обоснование |
|---|---|---|
| B-1, minor | Исправить до acceptance | `coarse reason`, `existence oracle` и `leeway` являются смыслообразующими терминами; их нужно объяснить в локальном словаре learn brief обычным русским языком. |
| B-2, note | Исправить тем же проходом | Добавление `leeway=0` в краткое описание interview устраняет последнее текстовое расхождение закреплённого validator contract. |
| A-1, note | Без правки | Более новые patch-релизы Python и cryptography не меняют применимость материала; baseline не обязан автоматически совпадать с latest. |
| A-2, note | Зафиксировать как ограничение будущих пакетов | Для будущего slice с `FileResponse`/Range требуется отдельный freshness/readiness выбор с учётом Starlette `>=1.5.1`; текущий S05 не использует эту поверхность. |
| A-3, note | Без правки | Материалы уже требуют единый error mapper и проверку собранного ASGI/HTTP пути; наблюдение о default `HTTPBearer` полезно реализации, но не обнаруживает дефект спецификации. |

## Условия acceptance-pass

- B-1 и B-2 имеют отдельные видимые исправления и mapping в handoff автора.
- Пять учебных материалов остаются в `review` до оркестраторского acceptance-pass.
- Semantic IDs, 15 relationships, 4 targets, роли coverage, версии, fixtures, endpoint, response/audit contracts и evidence populations не меняются.
- Канонический consolidated-файл существует отдельно от профилей A и B; в его `sources` нет самоссылки.
- Восстановленный профиль B явно сообщает provenance и не выдаётся за побайтовый оригинал.
- После точечной проверки оркестратор переводит материалы и регистрации M1.8.9 в `accepted`, фиксирует G9 и обновляет программные артефакты; module gate автоматически не присваивается.
