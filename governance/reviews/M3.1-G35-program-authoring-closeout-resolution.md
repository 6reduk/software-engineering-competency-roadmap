# M3.1 — решение оркестратора по G35

## Решение

Финальный authoring close-out фактически и структурно состоятелен. Он завершает
режим создания материалов, сохраняет learner execution неподтверждённым и оставляет
один честный input вместо случайного выбора задания.

M3.1 пока не принят: один minor требует локально объяснить внутренние английские
ярлыки при первом употреблении. Выполняется correction-pass по
`governance/work-packages/M3.1a-G35-findings-correction.md`.

## Disposition

| Finding | Решение |
|---|---|
| C-1 minor | Исправить до acceptance точечными русскими пояснениями десяти терминов и корректным порядком «русский смысл → английский термин в скобках» |
| C-2 note | No change в M3.1a. Возможный перенос инструкции и уточнение третьего поля остаются редакционным backlog, поскольку действие уже названо до audit-блоков и неоднозначность не блокирует следующий ответ владельца |

## Граница

Correction меняет только тело close-out и не меняет front matter, stop authoring,
12/2/1 project-spec, портфельные claims, открытый input, owners, среду, return
triggers или lifecycle. Автор не выбирает spec, не запускает runtime, не повторяет
G35 и не объявляет acceptance.

После handoff нужен точечный verification-pass C-1. Только отдельный
acceptance-pass может принять M3.1 и окончательно закрыть текущий program authoring.
