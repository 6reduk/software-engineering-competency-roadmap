## Required changes

### 1. Обновить snapshot и artifact registry

- Зафиксировать snapshot 2026-08-30 и acceptance M1.8.11.
- Добавить пять S14 operation-cost artifacts после существующих entities с устойчивыми локальными кодами, kind, primary module и точным количеством relationships.
- Не менять исторические relationships первых 37 artifacts.
- Считать relationship как пару `(target, role)`.

### 2. Пересчитать outcome audit

- Добавить все 13 YAML relationships M1.8.11 к exact targets.
- Сохранить ровно один канонический ряд на каждый из 69 outcomes.
- Не считать capability-level `reference` outcome evidence.
- Не считать `probe` proficiency evidence; отдельно пересчитать `probe-only`.
- Проверить, что Abuse L1–L3 впервые получили execution-oriented evidence, а Abuse L4 остался пустым либо probe-only согласно фактическому реестру.
- Не приписывать Identity, Load Control, A3, B3, B5 или B7 coverage за linked context, Gate 0 и переиспользованные contracts.

### 3. Пересчитать module states и DAG effects

Обязательно проверить:

- изменяет ли Abuse L1–L3 состояние Identity and API security boundaries при уже принятом S05 flow;
- отсутствие Identity L4, Abuse L4 и module-gate decision не допускает automatic `complete`;
- operation-cost readiness не закрывает aggregate quota/rate, callback/untrusted-target/SSRF или общий A3 baseline;
- supporting relationships других slices не создают автоматического завершения соседних modules;
- изменилось ли prerequisite readiness downstream modules, не смешивая hard DAG с внешними A3/B3/B5 readiness gates.

### 4. Пересобрать очередь

Сравнить минимум четыре кандидата:

- Application Caching/S15 с отдельным B3 cache-store readiness и при необходимости B5 coordination readiness;
- оставшаяся callback/untrusted-target/SSRF половина S14 как отдельный пакет с собственным A3/network readiness;
- узкий HTTP Service Runtime completion вокруг S01/S02 без повторения cancellation/pool/degradation;
- External Service Integration/S08 либо другой строго bounded primary action без повторения fan-out/deadline/retry evidence.

При необходимости заменить слабого кандидата completion-tail существующего partial module. Для каждого оценить hard prerequisites, external readiness, ценность двум RoleViews, новое уникальное outcome coverage, boundedness, риск повторения принятых slices и пригодность полного learning flow.

Не считать принятый operation-cost slice полным закрытием S14. Не переносить его synthetic cell model на callback/SSRF, quota/rate, cache или external integration.

### 5. Выбрать один следующий package

Decision brief обязан содержать:

- один module;
- один primary scenario и не более двух supporting scenarios;
- одно центральное наблюдаемое действие;
- primary/supporting capabilities и exact outcome candidates;
- ссылки на принятое coverage, которое нельзя повторять;
- минимальный полный flow `index + learn + interview + kata + project-spec` либо явное обоснование более узкого набора;
- внешний readiness gate внутри будущего authoring package, если он необходим;
- non-goals, risks/open questions и минимум две сильные отвергнутые альтернативы.

Не создавать следующий authoring work package и не писать учебный content.
