## Required changes

### C-1 — различимый stale-backfill defect

Без готового SQL уточнить Defect и будущий Gate 0:

- наивный перенос сначала читает и сохраняет старое значение до барьера, затем отдельным шагом пытается записать именно сохранённое значение после подтверждённого W-old;
- Gate 0 до полного опыта фиксирует isolation level соединений backfill и W-old;
- заранее объявляется ожидаемая сигнатура Defect: применённое расхождение либо отвержение записи с конкретным SQLSTATE;
- одношаговый `UPDATE`, который после ожидания повторно проверит условие на свежей версии строки и тем самым превратит Defect в Fixed, не считается подтверждением сценария;
- короткая предварительная проба обязана воспроизвести выбранную сигнатуру до полного control/defect/fixed.

Не предписывать конкретный SQL, библиотеку или единственную реализацию барьера.

### C-2 — авторитет суммы

Уточнить инвариант и oracle: авторитетно последнее подтверждённое изменение суммы через W-old либо W-new. Backfill — техническое копирование и не становится новым бизнес-изменением суммы только потому, что его запись подтверждена. В Defect эталон для конкурентно изменённой строки остаётся 12000.

### C-3 — topology соединений

Согласовать описание topology и readiness: шесть ролей/соединений — W-old, W-new, backfill, DDL/validation, наблюдатель и отдельный writer-сеанс lock-пробы. Если реализация будущего Gate 0 безопасно совмещает роли, это должно быть явно обосновано; по умолчанию readiness проверяет все шесть.

### C-4 — человеческий статус

Заменить `Gate 0 и эксперимент: **NOT_RUN**` человеческой формулировкой: лабораторный опыт и предварительная проверка среды до создания учебных материалов не выполнялись. При первом употреблении объяснить Gate 0 как такую предварительную проверку. Не вводить новый metadata status.

### C-5 — первые употребления терминов

Локально, без массового глоссария, объяснить при первом употреблении:

- проверку ограничения хранилища (`validation`) отдельно от сверки данных;
- заранее заданные строки (`fixtures`);
- читателей и писателей приложения (`readers/writers`);
- текст/сценарий технической пробы (`probe`);
- стартовый каркас (`scaffold`).

После правки слова «сверка» и `validation` не должны обозначать одно действие.

### C-6 — честное пятое состояние

Переименовать строку «Копейки обязательны» так, чтобы она обозначала конец опыта без демонтажа старого пути, например: «Завершение опыта: новое представление обязательно, старое сохранено». Содержимое R-old/W-old/R-new/W-new не менять.

### C-7 и C-8 — обязательные входы будущего Gate 0

В readiness или открытых вопросах явно записать, не принимая решение вместо будущего опыта:

- определить допустимость отрицательных и избыточно точных сумм, соответствующие ограничения и отрицательные пробы; округление значением типа не считать отвержением входа;
- выбрать и проверить порядок включения механизма совместимости и ограничения согласованности так, чтобы W-old оставался допустимым в каждой заявленной точке; преждевременное enforcement не считать корректным переходом.

Эти два пункта остаются `не подтверждены`; они не требуют runtime experiment в correction-pass.
