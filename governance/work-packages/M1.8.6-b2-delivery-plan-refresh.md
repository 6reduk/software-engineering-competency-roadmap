## Required changes

### 1. Обновить snapshot и artifact registry

- Зафиксировать snapshot 2026-08-24 и acceptance M1.8.5.
- Добавить пять S07 artifacts после существующих entities с устойчивыми локальными кодами, kind, primary module и точным количеством relationships.
- Не менять исторические relationships первых 22 artifacts.

### 2. Пересчитать outcome audit

- Добавить все 22 YAML relationships M1.8.5 к exact targets.
- Сохранить ровно один канонический ряд на каждый из 69 outcomes.
- Не считать capability-level `reference` outcome evidence.
- Не считать `probe` proficiency evidence; отдельно пересчитать `probe-only`.
- Показать пять впервые покрытых outcomes без приписывания B3/B5 coverage.
- Сохранить отсутствие Idempotency L4 и фиктивного module completion.

### 3. Пересчитать module states и DAG effects

Применять принятые определения `complete / partial / not-started / blocked` и D-044.

Обязательно проверить:

- Transactional Persistence Integration: `not-started → partial` за счёт Transaction L1–L3 и Idempotency L2–L3;
- supporting idempotency evidence не завершает Background Workflows или другой module;
- изменилось ли prerequisite readiness downstream modules, но не путать hard DAG с external conditional baseline;
- ни один module не становится `complete` без явного module-gate decision;
- B3 readiness M1.8.5 является substrate gate S07, а не общим доказательством proficiency B3.

### 4. Пересобрать очередь

Сравнить минимум четыре кандидата:

- Identity-aware Boundaries — S05;
- API Security & Abuse Controls — S14;
- Application Caching — S15;
- Background & Message-driven Workflows — S09;

При необходимости добавить один completion-tail, если он даёт больший leverage. Для каждого оценить hard prerequisites, external A3/B3/B5 readiness, роль для двух RoleViews, пустое primary coverage, новое уникальное outcome coverage, boundedness действия, риск дублирования и пригодность полного flow.

Не выбирать S05/S14 при неподтверждённом A3 baseline молча: либо встроить минимальный readiness gate в будущий authoring package по правилу D-046, либо выбрать другой кандидат и явно обосновать решение. Аналогично применять B3 readiness к S15 и B5 language boundary к S09.

### 5. Выбрать один следующий package

Decision brief обязан содержать:

- один module;
- один primary scenario и не более двух supporting scenarios;
- одно центральное наблюдаемое действие;
- primary/supporting capabilities и exact outcome candidates;
- ссылки на принятое coverage, которое нельзя повторять;
- минимальный полный flow `index + learn + interview + kata + project-spec` либо явное обоснование более узкого набора;
- external readiness gate внутри будущего authoring package, если он необходим;
- non-goals, risks/open questions и минимум две сильные отвергнутые альтернативы.

Не создавать следующий authoring work package и не писать учебный content.
