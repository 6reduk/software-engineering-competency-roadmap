## Required changes

### B-1 — терминология

В локальный словарь learn brief добавить три коротких определения в контексте slice:

- **Coarse reason / укрупнённая причина** — намеренно недетальная внутренняя категория решения, достаточная для диагностики и не раскрывающая криптографические детали или данные чужого объекта.
- **Existence oracle / канал различения существования** — наблюдаемое различие ответов, по которому caller может угадать, существует ли недоступный ему объект.
- **Leeway / допуск рассинхронизации часов** — допустимое отклонение времени при проверке `exp` и `nbf`; `leeway=0` означает, что закреплённый лабораторный validator такого допуска не предоставляет.

Согласовать первое употребление терминов с правилом «русское объяснение → английский термин в скобках». Не расширять brief в общий JWT/security tutorial.

### B-2 — единый validator contract в interview

В разделе с историей для кандидата `interview/valid-token-cross-tenant-order.md` добавить `leeway=0` в перечисление закреплённых параметров проверки токена. При первом употреблении дать короткое русское пояснение либо сослаться на уже введённое в этом же файле определение; файл должен оставаться автономной точкой входа.

### R-1 — каноническая консолидация

До перезаписи `-kimi.md` сохранить его текущее содержимое как `governance/reviews/M1.8.9-G9-identity-aware-boundaries-consolidated.md`, затем привести новый файл к конвенции:

- уникальный `id` с суффиксом `-consolidated`;
- `kind: review`, `status: review`, `owner: orchestrator`, `profile: consolidated`;
- `sources` с отдельными путями профилей A и B, без ссылки файла на самого себя;
- заголовок и вводная часть не должны утверждать, что consolidated расположен по пути `-kimi.md`;
- сохранить verdict `accepted_with_changes`, все пять findings/dispositions, runtime evidence, coverage-пересчёт и рекомендацию по acceptance.

### R-2 — восстановленный профиль B

Восстановить `governance/reviews/M1.8.9-G9-identity-aware-boundaries-kimi.md` как отдельный профиль B, используя только явно сохранённый внутри текущей консолидации снимок исходного результата B. Файл должен содержать:

- `id` с суффиксом `-kimi`, `kind: review`, `status: review`, `owner: independent-reviewer`, `profile: B`, `model: kimi`;
- исходный verdict B: `accepted_with_changes` — `0 blocker / 0 major / 1 minor / 1 note`;
- B-1 и B-2 с evidence/recommendations;
- таблицу критериев, выводы по readability, Identity L1–L3, coverage и kata/project в объёме встроенного снимка;
- явный provenance-блок: файл восстановлен 2026-08-27 из снимка профиля B, включённого в ошибочно размещённую консолидацию; побайтовая идентичность утраченному исходнику не заявляется; содержательные findings и verdict не изменены.

Нельзя придумывать новые проверки, findings или подтверждения от имени исходного reviewer. Если встроенного снимка недостаточно для конкретной секции, честно отметить границу восстановления вместо реконструкции по догадке.
