# M3.1a — correction findings G35

## Objective

Закрыть только C-1 консолидированного G35: объяснить внутренние английские ярлыки
при первом содержательном употреблении в финальном program authoring close-out.

Не выбирать project-spec, не заполнять открытый input и не выполнять learner
execution.

## Ownership

Изменить ровно один файл:

- `governance/state/PROGRAM-AUTHORING-CLOSEOUT.md`.

Другие файлы не менять и не создавать. Front matter сохранить побайтово.

## Required correction

При первом содержательном употреблении использовать порядок
«русский смысл → английский термин в скобках», после чего допустимо короткое
английское обозначение:

1. `authoring` — создание материалов программы;
2. `curriculum` — учебная программа;
3. `project-spec` — проектная спецификация;
4. `handoff` — передача результата/контекста следующему владельцу;
5. `coverage` — связи материалов с учебными результатами;
6. `revision` — однозначно закреплённая редакция файла;
7. `Gate 0` — предварительная лабораторная проверка среды автором;
8. `module gate` — отдельное решение о завершении модуля;
9. `ImplementationReference` — проверенная ссылка на реализацию;
10. `return triggers` — наблюдаемые условия возврата к authoring.

Ориентироваться на точные места B-1:

- строки около 13, 18, 22, 25 и 30;
- шаблон и пояснение revision около 64–73;
- Gate 0 около 85–96;
- таблица ответственности около 108–113;
- заголовок возврата около 119–121.

Не размножать определения во всех повторных вхождениях. Не переписывать абзацы
целиком, если достаточно локальной замены.
