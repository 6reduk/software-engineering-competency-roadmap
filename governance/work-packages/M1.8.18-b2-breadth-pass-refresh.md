## Required changes

### 1. Обновить snapshot и artifact registry

- Зафиксировать snapshot 2026-09-08 и acceptance M1.8.17.
- Добавить пять External Integration artifacts после существующих entities с устойчивыми локальными кодами, kind, primary module и точным количеством relationships.
- Не менять исторические relationships первых 52 artifacts.
- Считать relationship как пару `(target, role)`.

### 2. Пересчитать outcome audit

- Добавить все 9 YAML relationships M1.8.17 к exact targets.
- Сохранить ровно один канонический ряд на каждый из 69 outcomes.
- Не считать capability-level `reference` outcome evidence.
- Не считать `probe` proficiency evidence; отдельно пересчитать `probe-only`.
- Проверить, что External L1/L2 получили собственный primary-module flow, но не стали новыми unique outcomes.
- Не приписывать External L3/L4, Verification, Cancellation, Load Control, A3 или B5 coverage за linked context, Gate 0 и переиспользованные contracts.

### 3. Пересчитать module states и зафиксировать фазовый переход

Обязательно проверить:

- переход External Service Integration из `not-started` в `partial` без automatic `complete`;
- отсутствие External L4 и отдельного module-gate decision;
- неизменность internal hard DAG и локальность A3/B5 readiness M1.8.17;
- остались ли модули `not-started`;
- факт, что `partial 10/10` означает завершение первого breadth-pass по собственным flows, но не completion десяти modules;
- какие gaps являются обычным материалом L1–L3, а какие требуют cross-team/migration/adoption evidence L4 и не могут быть честно закрыты ещё одной спецификацией.

### 4. Пересобрать очередь как выбор следующей фазы

Сравнить минимум шесть кандидатов:

1. **B2 consolidation/module-gate package**: карта принятых flows, критерии module completion, gap/debt registry, навигация и readiness к самостоятельным ImplementationReference — без нового proficiency coverage.
2. **Evolution L1**: один bounded execution task только если он даёт новое действие и не повторяет additive API change S03.
3. **HTTP Service Runtime completion** вокруг S01/S02 без повторения cancellation, pool saturation, API evolution и validation/error-contract testing.
4. **Callback/untrusted-target/SSRF** половина S14 с отдельным A3 network/DNS/redirect Gate 0.
5. **Aggregate quota/rate control** с явным store/coordination readiness без повторения operation-cost admission.
6. **L4 adoption/migration package** только если можно назвать реальное cross-team evidence, артефакт принятия и boundary участия; handbook/project-spec без выполнения не считается L4 proficiency.

Дополнительно разрешено сравнить External L3, Cache/Workflow/Delivery completion-tail или вторую вертикаль, если кандидат остаётся bounded и опирается на фактический gap. Не выбирать тему только ради увеличения числа relationships.

Для каждого кандидата оценить:

- hard prerequisites и external readiness;
- ценность Backend/Distributed Systems и Architecture/Technical Leadership RoleViews;
- новое уникальное outcome coverage и более важное собственное execution evidence;
- boundedness и риск повторения accepted slices;
- необходимость реального multi-team/adoption контекста;
- пригодность полного learning flow;
- почему пакет нужен сейчас, а не после consolidation либо перехода к следующей вертикали.

### 5. Выбрать один следующий bounded package

Разрешены два класса решения:

- один новый content slice с одним central action и честным outcome scope;
- один consolidation/module-gate package без нового учебного content, если breadth-pass завершён и следующий риск — связность, навигация, gate criteria и накопленный долг.

Decision brief обязан содержать:

- тип пакета и один владеющий module/program concern;
- central observable result;
- exact scope и non-goals;
- primary/supporting capabilities и outcome candidates либо явное `no new coverage`;
- external Gate 0, если он нужен;
- минимум две сильные отвергнутые альтернативы;
- критерий, после которого снова выбирается content authoring, consolidation или переход к следующей вертикали.

Не создавать следующий work package и не писать учебный content.
