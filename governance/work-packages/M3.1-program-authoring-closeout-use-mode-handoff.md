# M3.1 — close-out authoring и передача в режим использования

## Objective

Создать один финальный программный close-out, который фиксирует окончание текущего
детального authoring и даёт один конкретный старт learner execution по уже
принятому project-spec.

Это handoff из режима создания материалов в режим их использования. Он не создаёт
новую вертикаль, учебный материал, реализацию участника или доказательство навыка.

## Ownership

Создать ровно один файл:

- `governance/state/PROGRAM-AUTHORING-CLOSEOUT.md`.

Другие файлы не менять. Не создавать blueprint, intake новой вертикали, Gate 0,
coverage, semantic IDs, kata/project-spec, ImplementationReference, review,
acceptance, STATUS/DECISIONS update или runtime implementation.

## Context manifest

Полностью прочитать:

1. `governance/planning/intakes/program-depth-checkpoint.md`;
2. `governance/reviews/M3.0-G34-program-depth-checkpoint-acceptance.md`;
3. `curriculum/tracks/b2/consolidation/README.md`;
4. `curriculum/tracks/b2/consolidation/routes-and-reuse.md`;
5. `curriculum/tracks/b2/consolidation/implementation-readiness.md`;
6. `curriculum/tracks/b3/phase-closeout.md`;
7. `curriculum/tracks/b5/phase-closeout.md`;
8. все существующие принятые project-spec B2/B3/B5 только для выбора одного
   стартового задания;
9. `curriculum/roles/backend-distributed-systems.md` и
   `curriculum/roles/architecture-technical-leadership.md`.

## Required result

Close-out должен:

1. человеческим языком сказать, что authoring остановлен по принятому M3.0, но
   обучение и выполнение участником ещё не завершены;
2. кратко зафиксировать портфель: B2/B3/B5 имеют первые глубокие проходы, остальные
   12 треков остаются awareness/skeleton/backlog;
3. выбрать ровно один существующий accepted project-spec как первый use-mode
   маршрут, не создавая нового задания;
4. объяснить выбор через целевую роль, доступность среды, различимый результат и
   отсутствие необходимости сначала писать новые материалы;
5. зафиксировать точный путь и revision выбранного spec, prerequisites, требуемую
   среду и минимальный первый evidence result;
6. если среда фактически не подтверждена, назвать конкретную проверку доступности и
   допустимый результат `blocked by <точное препятствие>` вместо выдуманной
   готовности;
7. отделить чтение от выполнения: нужны собственные файлы/данные, наблюдения,
   решение, границы вывода и отдельный review;
8. назвать owner следующего действия и owner отдельной оценки, не выполняя их;
9. повторить return triggers к authoring как исключение, а не очередь;
10. дать одну короткую команду/инструкцию следующего шага для участника без запуска
    runtime или создания репозитория.

Если доступный контекст не позволяет честно выбрать один spec по реальной задаче,
не выдумывать пользовательский кейс. В этом случае close-out фиксирует единственный
открытый input — выбор задачи владельцем программы — и даёт ограниченный шаблон из
трёх полей: `задача / доступная среда / первый результат`. Это считается честным
handoff, а не причиной возобновлять authoring.

## Non-goals

- Не закрывать curriculum, modules или proficiency.
- Не выполнять kata/project и не создавать reference implementation.
- Не выбирать C1/B7/B6 или иной новый authoring pass.
- Не пересчитывать весь coverage B2/B3/B5.
- Не превращать 12 треков в roadmap обязательных пакетов.
- Не вводить обязательную личную диагностику или анкетирование.

## Проверки

Проверить:

- создан ровно один файл;
- YAML и уникальность ID, если front matter используется;
- ровно один выбранный accepted project-spec либо честно один открытый input по
  правилу выше;
- путь/revision, среда и первый результат различимы;
- ссылки и anchors;
- отсутствие новых semantic entities, coverage и runtime claims;
- Markdown, UTF-8 без BOM, EOF, trailing whitespace и conflict markers.

SHA-256 snapshot доказывает только scope текущего запуска, не историческую чистоту
workspace.

## Handoff

Передать путь close-out, выбранный spec либо единственный открытый input, среду,
первый evidence result, owners и следующую инструкцию. Файл оставить в
`status: review`; review и acceptance не запускать.
