## Required changes

### C-1 — applicability matrix Abuse L2

В decision brief S14 рядом с exact outcome candidates добавить явное правило:

- четыре категории evidence criteria Abuse L2 являются обязательной applicability review для выбранного endpoint;
- категория получает threat case/control/evidence либо обоснованное `not applicable` с residual risk;
- Abuse L2 relationship запрещена, если хотя бы одна категория пропущена или её диспозиция не подтверждена Gate 0 и материалами.

Зафиксировать предварительную матрицу, не выдавая её за уже выполненный Gate 0:

| Категория | Предварительная диспозиция bounded package |
|---|---|
| Request/cost bounds | Центральное evidence: server-owned cost unit, admission до дорогой работы, request-shape bypass tests. |
| Field exposure | Gate 0 закрепляет fixed server-owned export schema либо allowlist; произвольный экспорт чувствительных полей запрещён. |
| Quota/rate | Distributed/time-based quota вне scope; per-operation ceiling не защищает от множества отдельных допустимых запросов — это residual risk. |
| Untrusted target rules | Callback/target отсутствует либо отвергается как неизвестный input; SSRF validation не проверяется и остаётся отдельным долгом. |

Сохранить L1–L3 как **кандидаты**, но явно указать: финальные relationships определяются только после Gate 0 и authoring evidence; L1/L3 также не начисляются автоматически.

### C-2 — SSRF-долг

В `Open questions и известный долг` добавить отдельный пункт:

- выбранный cost-admission package покрывает только одну половину канонического S14;
- arbitrary callback URL, untrusted-target validation и SSRF остаются непокрыты;
- нужен отдельный будущий bounded package с собственным Gate 0;
- метка S14 не считается закрытой после принятия cost-only slice.

Не добавлять SSRF в Scope, Gate 0 populations, kata или project текущего package.

### C-3 — классы первичных источников Gate 0

Заменить абстрактную формулировку «по первичным A3/B7 источникам» конкретным требованием проверить до authoring:

- официальный OWASP API Security материал по unrestricted resource consumption;
- официальную документацию выбранного framework по parsing/validation/binding;
- официальную документацию выбранного storage/runtime по стоимости и ограничениям операции;
- применимые HTTP/RFC источники для rejection/error contract;
- локальные воспроизводимые измерения как экспериментальное evidence с отдельной маркировкой, а не как нормативный внешний источник.

Не выбирать конкретный framework/storage и не заполнять Gate 0 в correction package.

### C-4 — десять строк очереди

Разделить объединённую строку `Service architecture / verification completion` на две строки:

- `Service architecture completion`;
- `Service verification completion`.

Сохранить их completion-tail смысл, относительный порядок и отсутствие artificial L4 package. После правки таблица содержит десять строк для десяти модулей; остальные позиции перенумеровать механически без изменения top candidates или decision brief.
