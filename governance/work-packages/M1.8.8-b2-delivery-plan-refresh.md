## Required changes

### 1. Обновить snapshot и artifact registry

- Зафиксировать snapshot 2026-08-26 и acceptance M1.8.7.
- Добавить пять S09 artifacts после существующих entities с устойчивыми локальными кодами, kind, primary module и точным количеством relationships.
- Не менять исторические relationships первых 27 artifacts.

### 2. Пересчитать outcome audit

- Добавить все 11 YAML relationships M1.8.7 к exact targets.
- Сохранить ровно один канонический ряд на каждый из 69 outcomes.
- Не считать capability-level `reference` outcome evidence.
- Не считать `probe` proficiency evidence; отдельно пересчитать `probe-only`.
- Проверить, что Workflow L2/L3 впервые получили execution evidence, а Workflow L4 остался пустым либо probe-only согласно фактическому реестру.
- Не приписывать B5, Idempotency, Cancellation или Verification coverage за переиспользованный контекст.

### 3. Пересчитать module states и DAG effects

Применять принятые определения `complete / partial / not-started / blocked` и действующие governance decisions.

Обязательно проверить:

- Background and Message Workflows: `not-started → partial` за счёт собственного S09 flow и Workflow L2/L3;
- Workflow L4, Idempotency L4 и отдельный module-gate decision отсутствуют, поэтому `complete` не присваивается;
- supporting relationships других slices не создают автоматическое завершение соседних modules;
- изменилось ли prerequisite readiness downstream modules, не смешивая hard DAG с external A3/B3/B5 baseline;
- B5 readiness M1.8.7 является substrate gate S09, а не общим доказательством B5 proficiency.

### 4. Пересобрать очередь

Сравнить минимум четыре кандидата:

- Identity-aware Boundaries — S05;
- API Security & Abuse Controls — S14;
- Application Caching — S15;
- External Service Integration — S08 либо другой строго bounded primary scenario этого module.

При необходимости добавить один completion-tail существующего partial module, если он даёт больший leverage. Для каждого оценить hard prerequisites, external A3/B3/B5 readiness, роль для двух RoleViews, пустое primary coverage, новое уникальное outcome coverage, boundedness центрального действия, риск дублирования и пригодность полного flow.

Не выбирать S05/S14 при неподтверждённом A3 identity/trust/security baseline молча: встроить минимальный readiness gate в будущий authoring package либо выбрать другой кандидат и явно обосновать решение. Для S15 отдельно проверить B3 cache-store behavior; S07 PostgreSQL readiness его автоматически не подтверждает.

### 5. Выбрать один следующий package

Decision brief обязан содержать:

- один module;
- один primary scenario и не более двух supporting scenarios;
- одно центральное наблюдаемое действие;
- primary/supporting capabilities и exact outcome candidates;
- ссылки на принятое coverage, которое нельзя повторять;
- минимальный полный flow `index + learn + interview + kata + project-spec` либо явное обоснование более узкого набора;
- внешний readiness gate внутри будущего authoring package, если он необходим;
- non-goals, risks/open questions и минимум две сильные отвергнутые альтернативы.

Не создавать следующий authoring work package и не писать учебный content.
