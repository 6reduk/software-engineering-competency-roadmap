## Required changes

### 1. Обновить snapshot и artifact registry

- Зафиксировать snapshot 2026-09-03 и acceptance M1.8.13.
- Добавить пять S15 caching artifacts после существующих entities с устойчивыми локальными кодами, kind, primary module и точным количеством relationships.
- Не менять исторические relationships первых 42 artifacts.
- Считать relationship как пару `(target, role)`.

### 2. Пересчитать outcome audit

- Добавить все 11 YAML relationships M1.8.13 к exact targets.
- Сохранить ровно один канонический ряд на каждый из 69 outcomes.
- Не считать capability-level `reference` outcome evidence.
- Не считать `probe` proficiency evidence; отдельно пересчитать `probe-only`.
- Проверить, что Cache L2/L3 впервые получили execution-oriented evidence, а Cache L4 остался пустым.
- Не приписывать Transaction, Load Control, Identity, Verification, B3 или B5 coverage за linked context, Gate 0 и переиспользованные contracts.

### 3. Пересчитать module states и DAG effects

Обязательно проверить:

- как Cache L2/L3 меняют membership coverage Transactional Persistence Integration, не создавая automatic `complete`;
- отсутствие Cache L4, Idempotency L4 и module-gate decision;
- B3 readiness относится только к cache substrate S15, а B5 признан неприменимым только для one-process claim; ни то ни другое не является proficiency coverage;
- supporting relationships не завершают соседние modules автоматически;
- изменилось ли prerequisite readiness downstream modules, не смешивая hard DAG с внешними A3/B3/B5 readiness gates.

### 4. Пересобрать очередь

Сравнить минимум пять кандидатов:

- Safe Service Evolution/S11 с центральным delivery/rollout действием и честным различием Delivery L1–L3/L4;
- External Service Integration/S08 с новым client action, не повторяющим fan-out/deadline/pool evidence runtime slice;
- оставшуюся callback/untrusted-target/SSRF половину S14 с собственным A3 network/DNS/redirect readiness;
- узкий HTTP Service Runtime completion вокруг S01/S02 без повторения cancellation/pool/degradation;
- completion-tail Transactional Persistence/Application Caching, только если есть достижимый локальный gap без искусственного Cache L4 или повторения S15.

Для каждого оценить hard prerequisites, external readiness, ценность двум RoleViews, новое уникальное outcome coverage, boundedness, риск повторения принятых slices и пригодность полного learning flow. При необходимости добавить более сильного кандидата, но не удалять из сравнения оба оставшихся `not-started` modules.

Не считать принятие S15 полным закрытием Transactional Persistence Integration. Не переносить one-process thresholds на distributed caching и не выбирать Cache L4 без migration/adoption evidence.

### 5. Выбрать один следующий package

Decision brief обязан содержать:

- один module;
- один primary scenario и не более двух supporting scenarios;
- одно центральное наблюдаемое действие;
- primary/supporting capabilities и exact outcome candidates;
- ссылки на принятое coverage, которое нельзя повторять;
- минимальный полный flow `index + learn + interview + kata + project-spec` либо явное обоснование более узкого набора;
- внешний readiness gate внутри будущего authoring package, если он необходим;
- non-goals, risks/open questions и минимум две сильные отвергнутые альтернативы.

Не создавать следующий authoring work package и не писать учебный content.
