## Required changes

### C-1 — явная предпосылка `dependency-exit`

В Gate 0 record, interview и kata явно зафиксировать:

- checkpoint `dependency-exit` наблюдается на success и error paths, потому что запись выхода размещена в `finally` вокруг `yield`;
- код, расположенный просто после `yield` без `finally`, может не исполниться при вбросе исключения в генератор зависимости;
- поэтому отсутствие такого checkpoint само по себе ещё не доказывает поломку assembly — сначала нужно проверить instrumentation;
- это уточнение относится к наблюдаемому trace и не меняет фактический порядок разворачивания dependency stack закреплённой сборки.

Формулировка должна быть человеческой и краткой. Не добавлять готовый probe или полный фрагмент решения kata; допустим короткий нейтральный пример формы `try: yield ... finally: record_exit()` только если без него правило остаётся двусмысленным.

### C-2 — однозначный объём recovery

В README и project-spec заменить сжатую запись recovery на однозначную арифметику:

- три повтора;
- в каждом повторе 20 последовательных операций: пять последовательностей `unavailable → ok → bad → ok`;
- всего recovery `3 × 20 = 60`.

Согласовать формулировки с уже точной таблицей kata. Не менять сами populations, число операций, watchdog, thresholds или итоги Gate 0.

### C-3 — handoff по принятой границе A-3

Исходный текст S01, scenario catalog и scope slice не менять. В handoff подтвердить, что:

- диагностическая потеря обязательного `X-Request-ID` остаётся узким частным случаем S01;
- status, media type и body в defect сохраняются;
- пакет не заявляет завершение всего S01 или HTTP Runtime module.
