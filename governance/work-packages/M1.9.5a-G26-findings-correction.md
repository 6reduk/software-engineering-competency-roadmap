## Required changes

### C-1 — вынести служебный evidence без изменения байтов

Из четырёх `<details>`-блоков work package восстановить и сохранить:

| Файл | Требуемая байтовая форма | SHA-256 |
|---|---|---|
| `probe.py` | UTF-8 без BOM, LF, один конечный LF | `ed81b839c79f7e014f872991653ef65d2d0524d744f00cfa514bd91ebca3fd2b` |
| `runtime.json` | UTF-8 без BOM, CRLF, без конечного перевода строки | `256c3cec4001207f30caa96db58c1d128cf1b65768ef9cdb21577359473ee84b` |
| `attempt1.json` | UTF-8 без BOM, CRLF, без конечного перевода строки | `8bd32ee0ff081eba6762502b43f6dcf50b7343ed0acda64153d719694e4f06c8` |
| `attempt2.json` | UTF-8 без BOM, CRLF, без конечного перевода строки | `5cb779babe123101160e5ec92eff26c0943888ea85dbcb1553f8e3696c91b26f` |

После успешного сохранения и проверки хэшей удалить из work package четыре полных `<details>`-блока от служебного `probe.py` до `attempt2.json`. Не реконструировать результаты вручную и не нормализовать JSON на другой отступ, порядок полей или окончания строк.

Вместо блоков оставить компактный раздел `Evidence index`, содержащий:

- объяснение, что файлы являются служебным evidence автора, а не scaffold, ImplementationReference или заданием участнику;
- относительные ссылки на четыре файла;
- таблицу `claim / файл / SHA-256 / byte convention`;
- locator образа, дату опыта и команду запуска либо ссылку на уже сохранённую команду Gate 0;
- правило: digest подтверждает неизменность доступного исходника, но digest без самого файла не доказывает опыт;
- явное указание, что профили A/B G26 и их runtime-повтор не становятся частью авторского evidence.

Человеческие разделы Gate 0 до исходников и рабочую историю после них сохранить. После переноса work package не должен содержать полный `probe.py`, JSON-журнал или готовое `CREATE TRIGGER` из оснастки.

Пять учебных материалов и B3 README не должны ссылаться на sidecar-файлы. Существующая ссылка coverage map на сокращённый work package остаётся неизменной.

### C-2 — объяснить термины при первом употреблении

Сделать только локальные правки там, где термин реально встречается. Использовать форму «русское объяснение → английский термин в скобках», не добавляя общий обязательный словарь:

- писатель приложения (`writer`);
- преобразование на пути приложения (`adapter`);
- заранее заданные строки (`fixtures`);
- стартовый каркас (`scaffold`);
- лабораторные предохранители (`guardrails`);
- действие ограничения на запись (`enforcement`);
- контрольный, дефектный и исправленный прогоны (`Control`, `Defect`, `Fixed`).

Также проверить `readback` и `oracle`: если конкретный автономный файл использует термин до собственного пояснения, перенести короткое объяснение к первому употреблению. Не заменять устоявшиеся технические обозначения повсюду и не переписывать разделы целиком.
